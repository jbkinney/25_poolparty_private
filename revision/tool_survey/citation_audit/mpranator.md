# Citation-integrity audit — MPRAnator

Record audited: `final/mpranator.md`

Sources checked: the canonical repository at commit `9969790d62410138d4281b7955da6d085f07b1bc`; the GitHub repository, tree, commits, tags, releases, forks, search, and metadata APIs; the two-page local paper PDF extracted with PyMuPDF; `btw584_supp.docx` downloaded from Europe PMC and parsed from `word/document.xml`; all current GenomeGeek documentation/form/download/result endpoints; the Sanger landing page and redirect; PyPI and Bioconda; and fresh GET/POST reproductions on 2026-08-14. This audit concerns citation accuracy only, not the record's ratings or conclusions.

## NOT FOUND IN ANY SOURCE

None. Every passage presented as a quotation was located in the paper, Supplementary, live documentation, live output, or repository. The non-verified items below are inaccurate counts, citations that do not support the full claim, live-behavior mismatches, or uncited provenance assertions—not fabricated quotations.

## Findings (every item not verified)

1. **Status: number-wrong. Record lines 17, 114, and 115.** The immutable recursive Git tree does not have 44 entries. GitHub's `git/trees/master?recursive=1` currently returns **50 entries: 41 blobs/files and 9 trees/directories**. `git ls-tree -r --name-only HEAD` likewise gives 41 files. The absence of `setup.py`, `requirements.txt`, `Dockerfile`, `LICENSE`, and `COPYING` is verified, but the repeatedly cited “44-entry recursive tree” count is not.

2. **Status: number-wrong. Record line 25.** The reconciliation says `additional_capabilities` changed from 10 items by “+5.” The extraction has 10 bullets and the final has 14 numbered items, so the net addition is **4**, not 5. The claimed fifth addition, PWM Seq-Gen dual-mode operation, was already the extraction's first additional capability (“Two modes: probabilistic realizations ... or exhaustive enumeration”).

3. **Status: number-wrong. Record lines 63 and 222.** It is false that “the four live forms submit a JS-generated `ordering` field.” Only the **Motifs and SNPs** forms contain the drag-and-drop list and append `<input ... name='ordering'>` in JavaScript. The Transmutation and PWM forms contain no `ordering` field. The reproduced missing-`ordering` HTTP 500 therefore applies to two forms, not four.

4. **Status: number-wrong. Record lines 46 and 116.** `q=MPRAnator` returning `total_count: 1` does not establish “no fork,” and that claim contradicts the record's own `1 fork` metadata. The GitHub forks endpoint returns one extant fork, **`xtmgah/MPRAnator`**. Default repository search omits forks, which explains the one-result search. The fork has no newer push than the canonical commit, but “no fork” is false; the search also cannot by itself prove “no successor.”

5. **Status: wrong-location. Record line 163.** The statement that repository `Part3Form` “lacks the reverse/complement options” is directly contradicted by the cited source. `iliasApp/forms.py:345–349` defines both `reverse = forms.BooleanField(...)` and `complement = forms.BooleanField(...)`; `views.py:164–194` reads and applies both. The repository does lack PWM Seq-Gen, but not these Transmutation options.

6. **Status: wrong-location. Record line 80.** The cited source does not support “Headers are generated entirely by the tool; the user never supplies them.” `oligo.py:74` inserts the user-provided `backgroundSequenceHeaderS` into the output header. SNP output derives its chromosome/range prefix from the user's FASTA header; Transmutation preserves the user's sequence name; PWM preserves the user's matrix header. The tool automatically generates descriptor suffixes, but users do supply the base identifiers.

7. **Status: wrong-location. Record lines 17, 114, and 210.** The evidence supports **two downloadable example scripts**, not the stronger statement that only “2 of 4 modules have any programmatic access at all.” All four live modules expose `<form method="POST" action=...>` result endpoints, and fresh programmatic POSTs produced Transmutation and PWM results as well as SNP results. Transmutation/PWM currently require the normal CSRF cookie/token flow; that does not make them non-programmatic. The accurate count attached to the cited evidence is “two modules have shipped API example scripts.”

8. **Status: wrong-location. Record lines 23–24, 78, 114, 179, and 210.** The current scripts do not “both 500 as distributed.” Each distributed script posts to an **`http://`** URL. On 2026-08-14, an actual `requests.post()` to that URL receives a 301 to HTTPS; `requests` changes the redirected request to GET, the result endpoint redirects again to the form, and the script ends at an HTTP 200 HTML form page. A direct HTTPS POST of the same payload does return 500, so the server-failure observation is real but is not the behavior of the script *as distributed*. The scripts still fail as usable Python 3 examples for another reason: they open a text file and call `write(result.content)`, where `result.content` is bytes, raising `TypeError` under Python 3. Historical 2026-08-10 response artifacts were not retained, so the claimed earlier “as distributed” 500 cannot be independently recovered.

9. **Status: wrong-location. Record line 193.** The Motifs “Load Sample Data” preset is not fully “mirrored in `MpraMotifs_script.py`.” The scaffold and two motifs match, but the live preset uses `leftDistance=3`, `rightDistance=3`, `frequencyOfInsertion=5`, and barcode values 12/20/80/2/4. Both the current served script and repository script use left/right 2, insertion frequency 1, and empty barcode parameters. The SNP preset is mirrored accurately; the Motifs preset is only partially mirrored.

10. **Status: wrong-location. Record lines 76–77 where `generatePermutations`/`equaliseSize` are cited as the implementation path.** Both functions exist, and their quoted comments are real, but they are not used by the Django Motifs result path. `views.py:78–99` calls `part1.generateCombinations()` and passes each combination directly to `oligo.oligo()`. `equaliseSize()` has no call site anywhere in the repository; `generatePermutations()` is called only in the `if __name__ == "__main__"` demonstration at `oligo.py:82–97`. The Supplementary and position-tuple enumeration still support combinatorial placement, but those two cited functions are dead/demo code rather than execution-path evidence.

11. **Status: number-wrong. Record lines 55, 130, and 156.** “Indels ≤10 nt” is not the implemented boundary. The public generation code uses `if abs(difference) < 10`, strictly excluding a 10-nt length difference, while form validation checks ALT allele length rather than indel length. Fresh live tests confirmed the mismatch: a 10-nt insertion encoded as anchored VCF `T -> GGGGGGGGGGG` was rejected with “SNP sizes cannot be greater than 10!”, and a 10-nt deletion (`11-nt REF -> 1-nt ALT`) emitted only the reference sequence. A 9-nt insertion was emitted. The Supplementary really does say “up to 10nt,” but the cited code/live tool implements a `<10` difference boundary and asymmetric allele-length validation.

12. **Status: number-wrong. Record line 194.** The documentation quote “This results in a total of 5856 sequences” exists verbatim, but the number cannot be reproduced from the public implementation and stated parameters. Applying the repository's actual `generateCombinations()` + `oligo()` logic to the two 90-nt backgrounds, motif lengths 7/9/14, edges 15, spacing 6–24, interval 12, and six barcodes gives **554 unbarcoded designs per background, or 554 × 2 × 6 = 6648 sequences**, not 5856. The deployed Motifs source is unavailable and the live module returns 500, so no alternate deployed calculation can be checked. The number is therefore a real documentation quotation but not a verified count.

13. **Status: number-wrong. Record line 220.** The final says the reviewer marked “21 of 24 verdicts supported,” but `reviews/mpranator.md` explicitly says: “**Twenty of the twenty-four cells I would leave alone.**” No separate structured review containing a 21/24 count exists in the survey directory. The final's 21/24 attribution is not supported by the cited review.

14. **Status: number-wrong. Record line 87.** The literal claim of a zero-hit grep over the **full recursive tree** for `codon|amino|protein|translat|orf|reading.frame` is false: vendored `iliasApp/static/iliasApp/bootstrap.min.css` contains many `transform`/`text-transform` occurrences that match the unbounded `orf` alternative. Excluding vendored CSS or using token-bounded biological terms produces the intended zero result, and no DMS feature was found; only the stated mechanical grep result is wrong.

15. **Status: minor-discrepancy. Record line 96.** `mycustom.py` does not contain “exactly three parsers” if parser classes are being counted. In addition to `FastaFile`, `BedFile`, and `SnpFile`, it defines and uses `FastaFileWithHeaderRange`, a distinct FASTA-header parser/subclass. “Three input format families” would be accurate; “exactly three parsers” is not.

16. **Status: minor-discrepancy. Record lines 126 and 244.** The source supports broad IUPAC handling, but not the unqualified claims “throughout” and “full IUPAC complement map.” `myfunctions.complement()` maps `S -> W` and `W -> S`; chemically correct IUPAC complements are `S -> S` and `W -> W`. Its regex classes such as `[A|G]` also include literal `|` as a character. The quoted live-doc sentence and the existence of all IUPAC keys are verified, but the implementation is not a fully correct IUPAC mapping.

17. **Status: minor-discrepancy. Record line 100.** The live documentation's LABEL vocabulary is not “exhaustive.” Actual live outputs contain `Position`, `Nucleotide change`, `REFERENCE`, `Mutated_nucleotides`, `Simulation number`, and `Prob`, none of which appears in the Motifs/SNP LABEL lists cited as exhaustive. No consequence annotation was found, so the row's negative evidence is otherwise supported; the characterization of the list as exhaustive is not.

18. **Status: minor-discrepancy. Record lines 52, 61, 73, and 99.** The record repeatedly conflates FASTA as the output *data format* with a plain-text HTTP response. Normal live POSTs to SNPs, Transmutation, and PWM return HTML result pages containing/embedding FASTA; separate download requests return `text/plain`. Fresh responses for all three working modules were HTML documents. The docs' statement that users can download a plain-text file is verified, but “each [form] returning ... a plain-text FASTA blob” and “every live output ... was plain-text FASTA” are too broad without the download-mode qualification.

19. **Status: minor-discrepancy. Record lines 61 and 229.** The literal statement “no importable module” is false: the repository contains ordinary importable Python modules (`mycustom.py`, `part1.py`, `part3.py`, etc.) and internal classes. What the evidence establishes is no **documented/supported installable library API or package**. The latter is accurate; the former absolute wording is not.

20. **Status: uncited. Record lines 8, 42, 63, 78, 114, 167, 177, 185, 220, 234, and 243.** The claimed audit provenance and request counts—“third independent pass,” “~30 fresh live HTTP requests,” “~10 live POSTs,” “three independent hosts/sessions,” and “~20 payloads”—have no retained request log, response artifacts, host/session identifiers, or timestamps in the record or survey directory. Representative statuses were reproducible on 2026-08-14 (Motifs 500, barcode-enabled SNPs 500, combinations 500, BED download 500, barcode-free SNPs 200, Transmutation 200, both PWM modes 200), but the historical counts and independence claims cannot be recomputed.
