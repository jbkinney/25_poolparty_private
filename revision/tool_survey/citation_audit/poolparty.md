# PoolParty citation-integrity audit

Audited record: `final/poolparty.md`

The stated local assessment tree (`poolparty-statecounter`, commit `1bb0179`) was checked directly, including source, documentation, tests, git metadata, and the installed environment. The canonical GitHub default branch, PyPI JSON/project page, Read the Docs site, and every URL in the record were checked live on 2026-08-14. Runtime claims that were fully specified were independently rerun where practical. Only non-verified items are reported below.

## NOT FOUND IN ANY SOURCE

1. **NOT FOUND IN ANY SOURCE — claimed `Party`-error reachability (record lines 86–94).** The record says the `RuntimeError` is reachable “only after an explicit `pp.init()` or outside an exited `with pp.Party()` block.” The source says the opposite for both named actions. `party.py:62-89` shows that `pp.init()` creates, enters, and activates a new default `Party`; `party.py:207-226` shows that exiting a `with pp.Party()` block restores the previous active party. Live, `pp.init(); pp.from_seq("ACGT")` succeeded, and `pp.from_seq("ACGT")` also succeeded immediately after `with pp.Party(): pass`. No public-source evidence supports the two claimed routes to the error.

2. **NOT FOUND IN ANY SOURCE — “every operation” is both a module function and a `Pool` method, and there are “40 distinct method-bound factories” (record lines 59–63, 96–100, and 749–755).** `stack`, `join`, and `sync` are public module functions but are not methods of `DnaPool` (`hasattr(DnaPool, ...)` is false for all three). The two maps at `__init__.py:331-387` do have 31 + 9 entries, but one entry is `generate_library`, not an operation factory, and they do not enumerate all public operations. Moreover, the loops at `__init__.py:390-399` only copy docstrings onto methods already supplied by mixin inheritance; they do not bind factories onto `Pool`. Thus the cited map count and cited binding lines do not support the claim as written.

3. **NOT FOUND IN ANY SOURCE — all library-algebra primitives are `Operation` subclasses (record lines 182–205).** `state_ops/sync.py` contains no `SyncOp` or other `Operation` subclass. Its sole public `sync(pools) -> None` function modifies each input pool's state in place (`sync.py:25-68`) and returns `None`, confirmed live. This also independently contradicts the record's absolute “Every operation is `Pool(s) → Pool`” statement.

4. **NOT FOUND IN ANY SOURCE — `get_kmers` eagerly “hold[s]” its source collection (record lines 157–162 and 965–970).** `GetKmersOp` stores only `length`, alphabet size, and the numeric total (`get_kmers.py:143-151`). It derives a requested k-mer from the current state index in `_value_to_kmer` and `_compute_core` (`:198-250`). There is no stored collection of k-mer source strings. The statement is true for `from_seqs`/`from_fasta`, but not for the third operation grouped with them.

5. **NOT FOUND IN ANY SOURCE — any operation can target a named region (record lines 837–841).** Region-aware sequence operations accept a `region` argument, but many public operations do not: for example `stack`, `sample`, `repeat`, `state_slice`, `state_shuffle`, `sync`, and `join`. The cited broad directories (`region.py`, `region_ops/`, and `docs/regions.rst`) document region-specific operations; they do not support the universal “any operation” claim.

6. **NOT FOUND IN ANY SOURCE — filter-heavy designs “silently shrink” and nothing is redrawn under constraint (record lines 632–635 and 924–929).** `generate_library.py:145-184` explicitly emits warnings when acceptance is too low, `max_iterations` is reached, or the state space is exhausted, so the shrinkage is not silent. Its public docstring at `:38-43` also says that with `num_seqs` and `discard_null_seqs=True` it “keeps sampling until N valid sequences are collected”; rejected random draws are therefore replaced by further draws. The source supports reject-only filtering, but not these two stronger absolute statements.

7. **NOT FOUND IN ANY SOURCE — all runtime dependencies are pure Python and have no compiled extensions (record lines 771–775 and 998–1002).** NumPy and pandas are compiled-extension packages. The assessed environment contains 63 NumPy/pandas `.so` files, including `numpy/fft/_pocketfft_umath.cpython-312-x86_64-linux-gnu.so` and `numpy/linalg/_umath_linalg.cpython-312-x86_64-linux-gnu.so`. `pyproject.toml` verifies dependency names and version floors only; it cannot support the claimed implementation property.

## Other non-verified evidence

1. **number-wrong — adversarial-review tally (record lines 20–24).** The cited review's actual tally at `reviews/poolparty.md:394-397` is `supported 26`, `understated 1`, and `unsupported as encoded 3`, over 30 reviewed values. The final record reports “29 of 33 values supported.” It then calls four verdicts non-supported while also naming `interface`, `last_activity`, `documented_examples`, and two additional rows (`combinatorial_motif_place`, `negative_control_generation`)—five distinct rows; the review explicitly labels those last two supported. The final tally is not a faithful count or description of the cited review.

2. **number-wrong — claimed 500–3000× construction/generation gap (record lines 146–147).** Recomputing the three ratios from the cited `examples/README.md:105-108` table gives MPRA `10.12/0.05 = 202.4×`, SpliceAI `15.08/0.03 = 502.7×`, and DMS `170.32/0.24 = 709.7×`. The supported range is approximately 202–710×, not 500–3000×.

3. **wrong-location — `join` concatenation and spacer evidence (record line 189).** `fixed_ops/join.py:13-33`, the cited range, constructs styles and spacer styles; it does not concatenate sequences. The `spacer_str` argument is at `:43-45`, length accounting at `:78-82`, and actual sequence concatenation is `spacer_str.join(seqs)` at `:87-90`.

4. **number-wrong — “8,000 unique CREs” and three barcodes for each unique arrangement (record lines 314–315, 462, and 817–818).** Rerunning the documented pre-repeat MPRA pipeline produced 8,000 rows but only 7,960 distinct `seq` strings; 40 rows were duplicates. The 1,000 sampled position configurations contained 995 distinct configurations, with five collisions, each propagated across eight orientations. `num_states=8000` is correct, but random sampling with replacement does not establish 8,000 unique CREs, and collided arrangements receive six—not three—barcodes after `repeat(times=3)`.

5. **number-wrong — last repository activity (record lines 782–796).** The canonical repository's default `main` branch already contained commit [`9d6a205`](https://github.com/jbkinney/poolparty-statetracker/commit/9d6a2058a5d0d4742d0874775b2f3a3de2f0706a), “Fix workflow file to properly test different Python versions,” dated 2026-04-13. That predates the record's 2026-08-10 assessment. `1bb0179` on 2026-04-07 is the last commit in the stale local checkout, not the canonical repository's last commit. The PyPI 0.1.1 date remains verified.

6. **number-wrong — exact readout grep count (record lines 725–736).** Repeating the stated case-insensitive regex `enrichment|count table|readout|fastq|bam` over source `.py` files returns seven hits, not zero, because `bam` matches `BamHI`: `restriction_enzymes.py:28,169,195,205`, `filter_mixin.py:217,249`, and `seq_properties.py:319`. These are lexical false positives and do not establish readout functionality, but the cited zero-hit result itself is false.

7. **wrong-location — location of all broad-tree `matplotlib` matches (record line 1031).** The narrowed claim of zero matches in `src/**/*.py` and `docs/**/*.rst` is verified. The follow-on statement that the only matches “anywhere” are in `docs/_build/html/` is not: the committed file `docs/_static/images/figure4b_g.drawio.svg` contains literal embedded metadata `Matplotlib v3.10.7`. This is a committed `_static` asset, not a `_build/html` asset.

8. **minor-discrepancy — exact infeasible-barcode count and timing (record lines 152–171 and 965–968).** The failure example omits a seed, so the exact accepted count is stochastic and is not reproducible evidence for “419.” An independent run of the displayed call reached 414 accepted barcodes before the same 100,000-attempt `ValueError`; the prior review records yet another value. The bare 24,000-barcode construction still stored exactly 24,000 strings, but took 0.091 s in the audit environment rather than 0.043 s. The behavioral claims (eager construction and fail-fast error) verify; the exact unseeded count and one-off timing do not.

9. **minor-discrepancy — `from_fasta` as an automatic coordinate-name exception (record lines 395–399).** Coordinate-derived names are created only in batch mode (`from_fasta.py:126-164`). Single-coordinate mode delegates to `from_seq` at `:109-125` and does not attach `{chrom}:{start}-{stop}({strand})` automatically. The later genome-coordinate section correctly qualifies this as batch-mode behavior; the automatic-naming section does not.

10. **minor-discrepancy — `pp.set_genetic_code` as support for reverse-translation host customization (record lines 594–603).** Passing `genetic_code=` directly to `reverse_translate` works, but `ReverseTranslateOp` constructs `CodonTable(genetic_code)` from its own argument, whose default is always `"standard"` (`reverse_translate.py:128-143`). It does not consult the active Party's table. Live, after `pp.set_genetic_code({'K': ['AAA', 'AAG']})`, default `pp.reverse_translate('K', codon_selection='first')` still produced `AAG`; supplying that dictionary explicitly produced `AAA`. The cited setter does not support this operation in the way the paragraph implies.

11. **minor-discrepancy — exact `num_states` and `seq_length` as universal pre-generation budget values (record lines 59–61 and 842–847).** `Pool.seq_length` explicitly returns `None` for variable-length pools (`pool.py:143-146`), as the record's own heterogeneous-stack example demonstrates. `num_states` is an exact state-space count, but after filtering the generated output may have fewer rows (`generate_library.py:38-43`). The source therefore supports exact state-space size and sometimes exact sequence length, not the unqualified claim that both are exact synthesis-budget quantities for every library.

12. **minor-discrepancy — PoolParty libraries can be `split` without generation (record lines 842–844).** The companion package exposes `statetracker.split(State, ...)` (`statetracker/ops/split_op.py:8-56`), but PoolParty exposes neither `pp.split` nor `Pool.split`, and no wrapper turns the returned raw `State` objects into split `Pool` libraries. Slicing, shuffling, and sampling are directly exposed and verify; “split” is only present at the lower-level companion API.

13. **uncited — 24 read-only executions and repository non-modification (record lines 14–18 and 51–52).** No command transcript, script, log, or other artifact enumerates the claimed 24 executions or records the before/after repository state. Many individual runtime outputs could be independently reproduced, but the historical execution count and “repository was not modified” assertion cannot be checked from any cited source.

14. **uncited — 168-state nested sub-pipeline (record lines 107–110).** The displayed expression replaces both operations' arguments with ellipses, and neither the record nor the cited source preserves the background sequence, region length, mutation settings, deletion settings, or an execution transcript. The source verifies that `apply_at_region` accepts a `Callable[[Pool], Pool]`, but the exact count 168 and example names cannot be recomputed from the evidence given.

15. **uncited — GC filter kept 32 of 64 and emitted 32 `NullSeq` rows (record lines 623–626).** The record gives `from_iupac('NNN')` but omits the `filter_gc` thresholds and generation arguments and provides no execution transcript. The 64-state input is recomputable; the exact 32/32 partition and warning are not determined by the cited source without the omitted parameters.

16. **dead-link — DOI placeholder (record line 1051; source `CHANGELOG.md:36`).** `https://doi.org/XXXX` returns HTTP 404. The record correctly calls it a placeholder, but it is still a cited dead URL.
