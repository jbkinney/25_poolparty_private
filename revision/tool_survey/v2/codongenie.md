No new primary-source verification was required for this re-score: every v2 row, including the seven new ones, is answerable from facts already established and cross-checked in the FINAL record (module-by-module source reading of all five `codon_genie` modules, the full git tree, the PDF, the PyPI wheel/sdist contents, and live HTTP probes of `https://codongenie.appspot.com`).

**Scoring conventions carried over from the FINAL record (§5 there), applied unchanged:**
- **C2** — a capability present in the installable package but unreachable from the tool's own UI/API scores **`partial`**, not `yes`.
- **C3** — where the tool performs a genuine, user-visible sub-step of a row's capability but not the full capability, score **`partial`** with an explicit scope note rather than `no`.
- The v1 `maintained` row has no v2 counterpart; its content is split across `installable_today` and `last_activity`.

| `library_first_class_object` | **partial** ⚠️ *(v1 `library_as_object` = no)* | CodonGenie never writes a file — its only output is a structured in-memory/JSON object the user holds, inspects and passes onward, and the Python client `CodonGenieClient.get_codons()` returns it directly as Python data. ## Fairness note for the response letter

CodonGenie is a purpose-built, deliberately minimal single-codon microservice ("∼700 lines of code", p. 6) and should be presented as **complementary to PoolParty, not a competitor**. It leads the matrix on `degenerate_iupac_codons`, is `yes` on `codon_optimization`, and holds four C3 `partial`s. It also carries capabilities no v2 row captures: the ranked library-size / specificity trade-off curve (pp. 2–3), exact per-codon library-size arithmetic, the reverse "Analyse" audit direction (which PoolParty has no analogue for), per-amino-acid redundancy surfaced as expected pool-composition skew (e.g. `DBK` @ 37762 → 18 variants with V over-represented 2:1), NCBI Taxonomy tree descent and synonym expansion over 35,792 organisms (`ncbi_tax_utils.TaxonomyFactory`), and alternative genetic-code support. Where the row set says `no`, the honest framing is scope, not deficiency — and never "CodonGenie can't do X" for anything the RidgeBio fork added.
