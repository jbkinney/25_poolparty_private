OPERATIONAL TEST (fixed 2026-08-10 BEFORE inspecting any tool):

For each tool, search its own source + official docs for NAMED, DOCUMENTED operations whose
OPERANDS AND RESULT are the tool's own library/design object (the type the tool produces as its
design output: a pool / library / variant set / oligo collection), implementing any of three
families:
  (a) COMBINE   - concatenate / stack / merge / union / add two or more libraries -> one library
  (b) SAMPLE    - sample / subsample / downsample a library -> smaller library
  (c) REPEAT    - repeat / replicate / multiply a library -> larger library

SCORING:
  yes     = all three families present as first-class operations of the design API
  partial = one or two families present, OR present only on a restricted/narrow type
  no      = none present; the user must combine/subsample with an EXTERNAL script

EXCLUSION (applied uniformly): generic container operations do NOT count -- python list +,
np.concatenate, pandas concat/append, Bio.Align.MultipleSeqAlignment.extend, torch.cat,
dict update. The operand must be a LIBRARY object of the tool and the operation must be part
of the tool's design API.
