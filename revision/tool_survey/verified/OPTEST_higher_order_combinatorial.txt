OPERATIONAL TEST — row higher_order_combinatorial
Fixed 2026-08-10 BEFORE inspecting any tool. Do not amend.

For each tool, search its own source for a construct that, from ONE user specification in ONE
invocation, ENUMERATES (itertools.product / itertools.combinations / nested per-site loops over
per-site variant sets) or RANDOMLY SAMPLES which >=2 independently-positioned sequence-altering
events co-occur inside a SINGLE output sequence. The decisive, re-runnable signature is
CARDINALITY GROWTH: the number of distinct output sequences the tool can emit from that one
specification grows multiplicatively / binomially in the number of candidate sites
(prod_i |V_i|, or comb(n,k)*|A|^k), not linearly (one event per output, sum_i |V_i|).

MOTIF DECISION (declared up front, applied identically to PoolParty and MPRAnator):
substituting or inserting a motif / k-mer at a position counts as a sequence-altering event on
exactly the same footing as an SNV. Therefore combinatorial MOTIF PLACEMENT qualifies as
higher-order iff the tool itself enumerates or samples WHICH combination of placements co-occurs
(i.e. cardinality grows multiplicatively). Deterministically stamping the same set of motifs
into every output oligo does NOT qualify, because cardinality does not grow combinatorially.

EXCLUSIONS (from rubric, restated operationally):
 X1  hand-authored multi-variant input (user-written VCF / CSV already listing the combination)
 X2  uniform context edits applied to every oligo (PAM protection, background variants)
 X3  one multi-base single event (3 bp parametric deletion = ONE event)
 X4  combinations the user obtains by re-running the tool and merging outputs
 X5  a generic sequence container / array type with no enumeration logic of its own

VALUES
 yes      combinatorial construct present in the tool's own API/CLI code path; cardinality
          multiplicative/binomial in sites.
 partial  combinatorial co-occurrence reachable but only on a restricted axis (e.g. only within
          one codon / one window / only 2 sites max), or only in an example script / notebook
          rather than the shipped API, or only as an unenumerated side-effect of a general
          optimiser.
 no       one designed event per output sequence; searched and absent.
 unknown  source genuinely inaccessible.
