# DNA Chisel fact-check

## Phase 1 — frozen source-first inventory

Inventory frozen on 2026-08-14, before opening the survey record. Sources used here are limited to the official v3.2.16 repository and documentation, the DNA Chisel PyPI project page, and `papers/Zulkower2020_dnachisel.pdf` (Zulkower and Rosser 2020). “Documented” means the capability is in the published documentation/API reference; “example-only” means the workflow is supplied as example code but is not a dedicated batch/library API; “source-only” means it is exported or implemented in v3.2.16 but omitted from the published built-in-specification reference.

### Package, access, and maintenance facts

- **Current release:** 3.2.16, released/uploaded **2025-05-10**. PyPI identifies it as the latest release and gives the source/wheel upload date; the repository tag `v3.2.16` points to commit `68c0930`. Evidence: [PyPI release history and provenance](https://pypi.org/project/dnachisel/#history), [GitHub releases](https://github.com/Edinburgh-Genome-Foundry/DnaChisel/releases/tag/v3.2.16), [`pyproject.toml`](https://github.com/Edinburgh-Genome-Foundry/DnaChisel/blob/v3.2.16/pyproject.toml#L1-L4).
- **License:** MIT. Evidence: [repository LICENSE](https://github.com/Edinburgh-Genome-Foundry/DnaChisel/blob/v3.2.16/LICENSE), [PyPI project metadata](https://pypi.org/project/dnachisel/).
- **Installation:** Python 3 package via `pip install dnachisel` for the minimal optimizer or `pip install 'dnachisel[reports]'` for plotting/PDF/report dependencies. Installing the package also installs the `dnachisel` CLI. Bowtie is separately required by `AvoidMatches`; local NCBI BLAST+ by `AvoidBlastMatches`; `primer3-py` by `AvoidHeterodimerization`. Evidence: [official installation section](https://edinburgh-genome-foundry.github.io/DnaChisel/#installation), [CLI documentation](https://edinburgh-genome-foundry.github.io/DnaChisel/ref/cli.html), [`AvoidHeterodimerization.py`](https://github.com/Edinburgh-Genome-Foundry/DnaChisel/blob/v3.2.16/dnachisel/builtin_specifications/AvoidHeterodimerization.py#L1-L48).
- **Availability/interfaces:** open-source Python library, command-line application, annotated-GenBank workflow, and a hosted CUBA web application. The paper describes all three interfaces and the public web app; the current project/PyPI pages still link the web app. Evidence: [project documentation home](https://edinburgh-genome-foundry.github.io/DnaChisel/), [PyPI description](https://pypi.org/project/dnachisel/), Zulkower2020 PDF pp. 1–2.
- **Maintenance:** the repository is public and not archived, and it had four releases from 2024-11-26 through 2025-05-10, including packaging/CLI fixes. However, as of the audit date its latest commit and release are both 2025-05-10 (15 months old). The evidence supports **available and maintained through May 2025, but not demonstrably under active ongoing maintenance in August 2026**; present activity is best called uncertain/low, not unqualified “actively maintained.” Evidence: [release history](https://github.com/Edinburgh-Genome-Foundry/DnaChisel/releases), [repository](https://github.com/Edinburgh-Genome-Foundry/DnaChisel), [PyPI history](https://pypi.org/project/dnachisel/#history).

### Phase 1 boundary conclusions

DNA Chisel’s core unit of work is one starting DNA sequence and one final edited DNA sequence. It is unusually composable and exposes low-level combinatorial tools (`MutationSpace.all_variants`, IUPAC expansion), a one-result constrained random generator, pairwise region compatibility, and official examples that loop over genes or greedily build compatible primer collections. Those capabilities make collection/variant workflows possible in Python. They do **not** amount to a native library-design object, batch CLI, joint diversity optimizer, Pareto/fitness-landscape sampler, indel designer, amino-acid sequence designer, or library-size/uniqueness controller. The official page assigns broad landscape-collection generation to the separate `dnachisel-dtailor-mode` project.

## A. FACTUALLY WRONG

1. **The record falsely says the source contains nothing named “variant.”**

   > “Absent from the specification set and from the entire source tree: anything named barcode, variant, mutagenesis, library, pool, HGVS, VCF, GFF, GTF.”

   The narrower conclusion that core DNA Chisel has no first-class variant-*collection* object is correct, but the quoted source-tree claim is not. The public core API has `MutationChoice.variants`, `MutationSpace.all_variants()` (a lazy Cartesian enumerator of sequence variants), and `DnaNotationPattern.all_variants()`. Evidence: [MutationSpace API](https://edinburgh-genome-foundry.github.io/DnaChisel/ref/core_classes.html#mutationspace), [`MutationSpace.py`, `all_variants`](https://github.com/Edinburgh-Genome-Foundry/DnaChisel/blob/v3.2.16/dnachisel/MutationSpace/MutationSpace.py#L132-L165), [pattern API](https://edinburgh-genome-foundry.github.io/DnaChisel/ref/core_classes.html#dnachisel.DnaNotationPattern).

2. **PSSM motif functionality is not avoidance-only.**

   > “All other motif handling in the tool is *avoidance*: `MotifPssmPattern` exists only as a `SequencePattern` for `AvoidPattern`-style constraints…”

   > “Motif functionality is *avoidance* only: `MotifPssmPattern` exists purely as a `SequencePattern` for `AvoidPattern`-style constraints…”

   `EnforcePatternOccurence` accepts any `SequencePattern`, counts its matches, and falls back to ordinary local constraint solving for patterns that are not `DnaNotationPattern`; consequently a `MotifPssmPattern` can be positively enforced to a requested occurrence count and can also be used as an objective. This does not create an MPRA/library workflow, but it directly refutes “avoidance only.” Evidence: [`EnforcePatternOccurence` API](https://edinburgh-genome-foundry.github.io/DnaChisel/ref/builtin_specifications.html#dnachisel.builtin_specifications.EnforcePatternOccurence), [`EnforcePatternOccurence.py`](https://github.com/Edinburgh-Genome-Foundry/DnaChisel/blob/v3.2.16/dnachisel/builtin_specifications/EnforcePatternOccurence.py#L19-L195), [SequencePattern API](https://edinburgh-genome-foundry.github.io/DnaChisel/ref/core_classes.html#sequencepattern).

3. **The success-report contents are overstated and success/failure artifacts are conflated.**

   > “`write_optimization_report` emits a bundle containing … an **md5 hash of the source file together with an embedded copy of the source file** … `logs.txt` from the problem logger, and before/after sequenticons.”

   `write_optimization_report` always writes the PDF, the two before/after CSVs, and the two GenBank outputs, but it does **not** write `logs.txt`; only `write_no_solution_report` does. The source hash/copy is written only when `file_path` is supplied. Evidence: [`write_optimization_report`](https://github.com/Edinburgh-Genome-Foundry/DnaChisel/blob/v3.2.16/dnachisel/reports/optimization_reports.py#L286-L423), [`write_no_solution_report`](https://github.com/Edinburgh-Genome-Foundry/DnaChisel/blob/v3.2.16/dnachisel/reports/optimization_reports.py#L82-L190).

4. **Edit annotations are not necessarily one feature per changed nucleotide.**

   > “`problem.to_record(..., with_sequence_edits=True)` writes … one feature per nucleotide edit labelled `before=>after`…”

   `sequence_edits_as_features()` first groups consecutive changed positions with `sequences_differences_segments()` and writes one feature per contiguous changed segment. Adjacent substitutions therefore share one feature. Evidence: [`sequence_edits_as_features`](https://github.com/Edinburgh-Genome-Foundry/DnaChisel/blob/v3.2.16/dnachisel/DnaOptimizationProblem/mixins/RecordRepresentationMixin.py#L194-L207), [`sequences_differences_segments`](https://github.com/Edinburgh-Genome-Foundry/DnaChisel/blob/v3.2.16/dnachisel/biotools/sequences_differences.py#L28-L42).

5. **The record presents a stale GenBank `@avoid_matches` annotation as part of the current default vocabulary.**

   > “Checked against the complete GenBank annotation vocabulary … `@avoid_matches`…”

   > “The GenBank annotation interface does not support all specifications — docs list `AvoidHeterodimerization` and `EnforceRegionsCompatibility` as ‘not yet supported as Genbank annotations’.”

   The published documentation does show `@avoid_matches`, but current v3.2.16 code does not register `AvoidMatches` in `DEFAULT_SPECIFICATIONS_DICT`; its class shorthand is instead `no_match`. Thus ordinary `DnaOptimizationProblem.from_record()` and the stock CLI cannot parse the documented `@avoid_matches` annotation unless a caller/server supplies a custom registry. This current-code/documentation disagreement is not flagged in the record. Evidence: [default registry](https://github.com/Edinburgh-Genome-Foundry/DnaChisel/blob/v3.2.16/dnachisel/builtin_specifications/__init__.py#L30-L61), [`AvoidMatches.shorthand_name`](https://github.com/Edinburgh-Genome-Foundry/DnaChisel/blob/v3.2.16/dnachisel/builtin_specifications/AvoidMatches.py#L59-L72), [documented server-dependent annotation](https://edinburgh-genome-foundry.github.io/DnaChisel/genbank/genbank_api.html#removing-homologies).

6. **The chronology of the `EnforceTranslation` additions is reversed.**

   > “`EnforceTranslation` gained alternative genetic codes (`genetic_table=`) and non-ATG start-codon policies (`start_codon=keep|ATG`) in v3.0.0, after the paper.”

   DNA Chisel 3.0.0 was released on **2019-11-16**, and its changelog lists both features. The paper was received on **2019-12-18** and published in 2020, so those features preceded even submission, not merely publication. Evidence: [PyPI release history](https://pypi.org/project/dnachisel/#history), [`changes.md`](https://github.com/Edinburgh-Genome-Foundry/DnaChisel/blob/v3.2.16/changes.md#v300), Zulkower2020 PDF p. 1.

7. **Not every objective is a biochemical or manufacturing score.**

   > “Every objective is a biochemical or manufacturing score: CAI, codon-usage matching, RCA harmonization, GC content, melting temperature, hairpins, homology, restriction sites, and the user-defined Gen9 9-mer synthesis score.”

   Built-ins include abstract edit-distance objectives such as `AvoidChanges` and `EnforceChanges`, and the documented `Specification` extension API permits arbitrary caller-defined scoring code. The record’s narrower conclusion that DNA Chisel ships no genomic-AI probing workflow is supported, but the universal statement about objective types is false. Evidence: [Specification API](https://edinburgh-genome-foundry.github.io/DnaChisel/ref/core_classes.html#dnachisel.Specification), [forcing changes](https://edinburgh-genome-foundry.github.io/DnaChisel/genbank/genbank_api.html#forcing-changes), [`EnforceChanges.py`](https://github.com/Edinburgh-Genome-Foundry/DnaChisel/blob/v3.2.16/dnachisel/builtin_specifications/EnforceChanges.py#L11-L91).

## B. INCOMPLETE

1. **Reverse translation and small sequence-generation utilities.** The record discusses `random_dna_sequence` and constrained random DNA but omits the exported `reverse_translate(protein, randomize_codons=...)` and `random_protein_sequence()` utilities, as well as the fact that `DnaNotationPattern.all_variants()` concretely expands IUPAC degeneracy. Evidence: [`random_sequences.py`](https://github.com/Edinburgh-Genome-Foundry/DnaChisel/blob/v3.2.16/dnachisel/biotools/random_sequences.py#L1-L66), [`reverse_translate`](https://github.com/Edinburgh-Genome-Foundry/DnaChisel/blob/v3.2.16/dnachisel/biotools/sequences_operations.py#L38-L70), [pattern API](https://edinburgh-genome-foundry.github.io/DnaChisel/ref/core_classes.html#dnachisel.DnaNotationPattern). **Materiality:** these are the package’s direct protein-to-DNA and degenerate-set generation primitives, even though neither is a protein optimizer or managed library workflow.

2. **`EnforceChoice` behavior and stability restriction.** It is only named in a list/vocabulary; the record never explains that it restricts a region to one of several same-length alternatives, expands IUPAC choices, and selects one compatible result, while the current source header still calls it work in progress. The same work-in-progress warning applies to `EnforceSequence`. Evidence: [`EnforceChoice.py`](https://github.com/Edinburgh-Genome-Foundry/DnaChisel/blob/v3.2.16/dnachisel/builtin_specifications/EnforceChoice.py#L1-L74), [`EnforceSequence.py`](https://github.com/Edinburgh-Genome-Foundry/DnaChisel/blob/v3.2.16/dnachisel/builtin_specifications/EnforceSequence.py#L1-L29). **Materiality:** explicit choice among alternatives is directly relevant to variant design, while the source warning materially tempers reliance on it.

3. **Fixed-length design and `SequenceLengthBounds` being verification-only.** The record lists `SequenceLengthBounds` as a synthesis constraint but omits its documented warning that it “can’t really be solved or optimized”; the core solver has no indel/length-changing operation. Evidence: [`SequenceLengthBounds` API](https://edinburgh-genome-foundry.github.io/DnaChisel/ref/builtin_specifications.html#dnachisel.builtin_specifications.SequenceLengthBounds), [core problem API](https://edinburgh-genome-foundry.github.io/DnaChisel/ref/core_classes.html#dnachisel.DnaOptimizationProblem). **Materiality:** readers could otherwise mistake a length checker for a sequence-length designer, a major boundary for library construction.

4. **Passive objectives and priority scheduling.** The record explains boosts/weighted scores but not `Specification.as_passive_objective()` or specification `priority`: a passive objective contributes during other objectives’ passes without getting its own optimization pass, and priority controls ordering. Evidence: [`Specification` API/source](https://github.com/Edinburgh-Genome-Foundry/DnaChisel/blob/v3.2.16/dnachisel/Specification/Specification.py#L227-L236), [core API](https://edinburgh-genome-foundry.github.io/DnaChisel/ref/core_classes.html#dnachisel.Specification). **Materiality:** these are distinct controls over how multiobjective designs are searched, not synonyms for objective weight.

5. **Edit-budget protection with `AvoidChanges`.** The record mentions freezing via `@keep` but omits `max_edits` and `max_edits_percent`, which can cap—not merely forbid—changes in a region or selected indices; it can also be used as a soft edit-minimization objective. Evidence: [`AvoidChanges` API](https://edinburgh-genome-foundry.github.io/DnaChisel/ref/builtin_specifications.html#dnachisel.builtin_specifications.AvoidChanges), [GenBank protection docs](https://edinburgh-genome-foundry.github.io/DnaChisel/genbank/genbank_api.html#sequence-protection). **Materiality:** bounded edit budgets are directly useful for controlled recoding and variant generation.

6. **`AvoidStopCodons` without translation preservation.** The class is named twice but its distinct mode is not explained: it removes/prevents stops in a frame while allowing non-synonymous changes, unlike `EnforceTranslation`, and it is absent from the default GenBank registry. Evidence: [`AvoidStopCodons` API](https://edinburgh-genome-foundry.github.io/DnaChisel/ref/builtin_specifications.html#dnachisel.builtin_specifications.AvoidStopCodons), [default registry](https://github.com/Edinburgh-Genome-Foundry/DnaChisel/blob/v3.2.16/dnachisel/builtin_specifications/__init__.py#L30-L61). **Materiality:** this is a materially different protein-related design regime from synonymous codon optimization.

7. **`UniquifyAllKmers` hard-constraint failure warning.** The record credits the homology control but omits the class warning that it may not work as a hard constraint when a subsequence occurs more than twice, although it can work as an objective. Evidence: [`UniquifyAllKmers.py`](https://github.com/Edinburgh-Genome-Foundry/DnaChisel/blob/v3.2.16/dnachisel/builtin_specifications/UniquifyAllKmers.py#L52-L68). **Materiality:** this limits one of the central claimed synthesis/homology constraints on repeat-rich designs.

8. **SnapGene import dependency.** The record says `.dna`/SnapGene input is supported but its dependency inventory omits the separately installed, undeclared `snapgene_reader`; without it, loading a `.dna` file raises `ImportError`. Evidence: [`genbank_operations.py`](https://github.com/Edinburgh-Genome-Foundry/DnaChisel/blob/v3.2.16/dnachisel/biotools/genbank_operations.py#L18-L36), [package dependencies](https://github.com/Edinburgh-Genome-Foundry/DnaChisel/blob/v3.2.16/pyproject.toml#L17-L42). **Materiality:** a reader choosing the advertised SnapGene interface needs this dependency for the interface to work at all.

9. **PSSM motif construction and positive enforcement.** Beyond the false avoidance-only characterization, the record omits that `MotifPssmPattern` can be built from equal-length sequence examples or JASPAR/MEME/TRANSFAC files with a score threshold and then supplied to generic pattern specifications. Evidence: [SequencePattern API](https://edinburgh-genome-foundry.github.io/DnaChisel/ref/core_classes.html#sequencepattern), [`MotifPssmPattern.py`](https://github.com/Edinburgh-Genome-Foundry/DnaChisel/blob/v3.2.16/dnachisel/SequencePattern/MotifPssmPattern.py). **Materiality:** this is DNA Chisel’s most expressive built-in regulatory-motif model, substantially broader than literal motif avoidance.

## C. BALANCE

The record is **broadly fair but somewhat limitation-heavy**. It gives substantial, specific space to DNA Chisel’s real strengths—composable constraints/objectives, constrained de-novo generation, lazy mutation-space enumeration, pairwise region compatibility, primer-collection and genome-loop examples, batch QC, codon/synthesis engineering, reports, and three interfaces—so it does not systematically hide the tool’s capabilities. However, the single-sequence/no-native-library boundary is repeated across many matrix rows and the limitations are documented at greater cumulative length than the positive capabilities. The main imbalance is therefore emphasis, not wholesale misrepresentation; the factual errors above include both overstatement (report artifacts) and understatement (variant and positive-PSSM functionality).
