# MPRAnator fact-check

## Phase 1 — frozen independent inventory

This inventory was completed and saved before the research record was opened. It is based only on the official GitHub repository, the official GenomeGeek documentation and live forms, the bio.tools registry entry, and the supplied paper. The deployed site is materially newer than the public repository snapshot, so evidence below distinguishes **current live interface**, **2015 repository implementation**, and **paper claim**.

### Scope

MPRAnator is a DNA/oligonucleotide design tool. Its current official site exposes four sequence-design modules: MPRA Motifs, MPRA SNPs, Transmutation, and PWM-SeqGen. No primary source documents protein/peptide-library generation, translation, codon optimization, amino-acid mutagenesis, or protein-specific scoring. The generic FASTA parser's permissiveness in some routes is not a documented protein capability; Transmutation explicitly targets nucleotide IUPAC symbols.

### Capability inventory

#### 1. MPRA Motif library construction

- **What it does:** substitutes supplied motifs into one or more background DNA sequences and generates sequences for every nonempty subset of the supplied motifs at positions satisfying user constraints. Because each motif in a subset is assigned positions through a Cartesian positional enumeration, the output can realize different spatial orders as well as single motifs and multi-motif combinations. Substitution preserves the background length.
- **Interface/API entry point:** current web form [`/MPRA/Motifs/`](https://www.genomegeek.com/MPRA/Motifs/) and result POST route `/MPRA/Motifs/Results/`; the site provides a downloadable Python `requests` client. In the repository snapshot, the routed entry points are `indexView`/`resultsView`, with `part1.generateCombinations()` and `oligo.oligo()` doing the generation.
- **Documented or example-only:** fully documented web capability. The HTTP parameterization is demonstrated in an “API script,” not defined by a versioned API schema. Repository Python functions are implementation internals, not a packaged public library API.
- **Controls:** reverse-complement-background checkbox; minimum and maximum spacing between motifs; minimum distances from the left and right edges; and an interval for motif substitution. The live form requires nonnegative integers for these five numeric controls. The interval is applied to the leftmost motif position in the repository implementation.
- **Output:** displayed and downloadable FASTA/plain text. Headers record the background, motif identities and zero-based positions, barcodes, adapters/restriction sites, and duplicate restriction-site warnings; the browser view highlights substituted motifs. The documentation explicitly explains that header position 53 corresponds to biological position 54.
- **Current live-form restrictions:** barcode length 10–25; barcode GC limits 0–100%; nominal edit distance at least 0; 0–100 barcodes per sequence; at most two labeled restriction-site fields and two labeled adapter fields. Spacing/edge/interval fields accept 0 in HTML, although interval 0 is incompatible with the repository's modulo operation.
- **Repository-snapshot restrictions (not safely attributable to the newer deployment):** FASTA is entered as text or upload, not both; at most 1,000 FASTA records and 20,000 nt per record; equal background lengths required; duplicate motif sequences rejected; `(number of motifs ** 4) * number of backgrounds <= 100`; then the routed implementation silently uses only the first 20 backgrounds and first 800 nt of each. Its barcode form permits only 1–5 per sequence, unlike the live form and the official six-barcode use case.
- **Implementation caveats in the public snapshot:** `revcompl()` complements but does not reverse (`backgroundS[::1]`), despite the “reverse complement” label. The documented “Levenshtein distance” barcode constraint is not implemented as Levenshtein or Hamming distance: the code counts matching positions and compares that count with the requested value; retry logic then does not recheck distance. GC bounds are strict rather than inclusive. Identical motif records are rejected, so the snapshot cannot directly encode repeated identical motifs even though the documentation discusses homotypic clusters.
- **Evidence:** [official documentation, motif parameters and output](https://www.genomegeek.com/MPRA/documentation/#collapseOne); [official worked example, including 5,856 sequences](https://www.genomegeek.com/MPRA/documentation/#collapseUseCase); [paper, p. 1 abstract and p. 2 Materials and methods](/mnt/c/Users/zhliu/Desktop/KinneyLab/25_poolparty_private/revision/tool_survey/papers/Georgakopoulos-Soares2017_MPRAnator.pdf); repository [`views.py` lines 23–125](https://github.com/hemberg-lab/MPRAnator/blob/master/iliasApp/views.py#L23-L125), [`forms.py` lines 299–336 and 402–499](https://github.com/hemberg-lab/MPRAnator/blob/master/iliasApp/forms.py#L299-L499), [`oligo.py` lines 12–78](https://github.com/hemberg-lab/MPRAnator/blob/master/oligo.py#L12-L78), [`part1.py` lines 15–21, 37–88, and 210–319](https://github.com/hemberg-lab/MPRAnator/blob/master/part1.py#L15-L319), and [`myfunctions.py` lines 10–25](https://github.com/hemberg-lab/MPRAnator/blob/master/myfunctions.py#L10-L25).

#### 2. Modular oligo assembly shared by Motif and SNP design

- **What it does:** appends a generated random DNA barcode, up to two user-supplied restriction-site strings, and up to two user-supplied adapter strings to each designed background/variant. A sortable interface controls the order of Barcode, Background, and each supplied restriction/adapter component. Thus arbitrary sequence text can be placed in the four labeled auxiliary slots, but the UI does not expose an unlimited general component graph.
- **Barcode generation:** user controls length, minimum/maximum GC content, nominal edit distance, and the number of barcoded replicates per designed sequence. If the complete barcode parameter set is absent, the repository produces an unbarcoded single copy. Barcode sequences use A/C/G/T and are intended to be unique.
- **Restriction checking:** output headers flag when an entered restriction motif occurs more than once in the assembled oligo (`DUPLICATE_RESTRICTION_SITES`). Matching uses an IUPAC-aware internal matcher and also attempts the opposite strand. This is a warning/annotation, not automatic removal or redesign.
- **Output bookkeeping:** headers number barcode replicates and record restriction/adapter presence; the actual barcode sequence is in the sequence, not the header. Output is FASTA-like plain text and downloadable.
- **Documented or example-only:** assembly, component ordering, and headers are documented web features. Duplicate-site matching mechanics and barcode algorithm details appear only in source.
- **Material restriction:** there are exactly two restriction and two adapter fields in the current UI. The paper's phrase “other sequence types of interest” describes using relevant subcomponents in these flexible slots, not a separate vector-design or arbitrary-component module.
- **Evidence:** [official documentation lines represented by the Motif and SNP sections](https://www.genomegeek.com/MPRA/documentation/); paper p. 2 (barcodes, adapters, restriction sites, drag-and-drop ordering, and possible use in viral/plasmid or non-MPRA designs); repository [`part1.py` lines 210–319](https://github.com/hemberg-lab/MPRAnator/blob/master/part1.py#L210-L319), [`part1.html` lines 73–163](https://github.com/hemberg-lab/MPRAnator/blob/master/iliasApp/templates/iliasApp/part1.html#L73-L163), and [`myfunctions.py` lines 28–76](https://github.com/hemberg-lab/MPRAnator/blob/master/myfunctions.py#L28-L76).

#### 3. MPRA SNP and small-indel library construction

- **What it does:** matches variants in VCF-like text to genomic ranges encoded in FASTA headers, substitutes each matching alternate allele, and emits reference and altered oligos. A checkbox selects separate single-variant designs versus combinations of all variants within each supplied sequence. Comma-separated multiallelic ALT fields are supported.
- **Small insertions/deletions:** the repository implementation supports length-changing alleles while keeping oligo length fixed. Insertions are balanced by trimming bases from an edge; deletions are balanced by padding an edge with `A`; headers report the adjustment. This behavior is relevant beyond literal SNPs even though the module is labeled SNP.
- **Interface/API entry point:** current web form [`/MPRA/SNPs/`](https://www.genomegeek.com/MPRA/SNPs/) and result POST route `/MPRA/SNPs/Results/`; downloadable Python POST example. Repository entry points are `mpraSnp`/`mpraSnpResults` and `parseSNPs.make_sequence_copies()`.
- **Documented or example-only:** single versus combinatorial variants, VCF/FASTA input, shared barcode/components, and FASTA output are documented. Multiallelic parsing and exact indel trimming/padding are source-only details. The paper explicitly says SNP design can study single or combinations of SNPs, and its broader introduction mentions small insertions/deletions.
- **Input restrictions in the public snapshot:** the FASTA header must contain `chr<chromosome>:<start>-<end>`. Its FASTA parser accepts numeric chromosomes 1–23 plus X/Y, while the variant parser accepts only 1–22 plus X/Y. Variant records are whitespace-separated and need at least the first five VCF columns; standard `#` header lines are not handled. The VCF chromosome value must omit `chr`. REF/ALT allow `A,T,G,C,U,.`; comma separates ALTs. The form rejects any ALT longer than 10 characters, and the generator processes only `abs(len(REF)-len(ALT)) < 10`. Repository FASTA limits are 50,000 records and 20,000 nt/record. There is no explicit variant-count cap, so combination count can be exponential.
- **Other source-only limitations:** REF is not verified against the background sequence; coordinate offset controls substitution. Backgrounds with no overlapping input variant are omitted. Combination-mode handling of deletion ALT `.` contains `change == ""` rather than assignment in one branch. Shared barcode/restriction/adapter constraints apply.
- **Live-form restrictions:** barcode length at least 10; GC bounds 0–100%; distance at least 0; barcode count is required and has HTML range 0–100; two restriction and two adapter slots.
- **Evidence:** [official SNP documentation](https://www.genomegeek.com/MPRA/documentation/#collapseTwo); paper pp. 1–2; repository [`mycustom.py` lines 145–188 and 241–301](https://github.com/hemberg-lab/MPRAnator/blob/master/mycustom.py#L145-L301), [`forms.py` lines 256–295 and 501–545](https://github.com/hemberg-lab/MPRAnator/blob/master/iliasApp/forms.py#L256-L545), [`parseSNPs.py` lines 5–208](https://github.com/hemberg-lab/MPRAnator/blob/master/parseSNPs.py#L5-L208), and [`views.py` lines 306–390](https://github.com/hemberg-lab/MPRAnator/blob/master/iliasApp/views.py#L306-L390).

#### 4. Transmutation control generation

- **What it does:** makes one transformed output for each input FASTA record using any combination of four options: scramble the whole sequence, reverse it, complement it, and mutate exactly a requested number of randomly selected positions. Reverse plus complement produces a reverse complement. This is intended to create MPRA negative/control sequences.
- **Operation semantics:** repository order is scramble → reverse → complement → random mutation. Scrambling is a simple mononucleotide shuffle. Mutation chooses distinct non-`N` positions; canonical A/C/G/T bases are always changed to another canonical base, while each ambiguity code is resolved to a canonical base outside its ambiguity set. `N` is not mutated.
- **Interface/API entry point:** current web form [`/MPRA/Transmutation/`](https://www.genomegeek.com/MPRA/Transmutation/) and `/MPRA/TransmutationResults/`; repository `part3View`/`part3RresultsView`, `part3.scramble_motifs()`, and `part3.mutateString()`.
- **Documented or example-only:** all four operations and IUPAC-nucleotide input are documented web features; exact mutation mapping/order is source-only. There is no advertised Transmutation API client.
- **Restrictions:** live mutation count is a required integer ≥0. Repository input limits are 1,000 records and 20,000 nt/record. Accepted source alphabet is `A,G,C,T,M,K,W,S,Y,R,H,V,D,B,N`; despite the docs' “all nucleic acid IUPAC letters,” `U` is not accepted. All-`N` input is rejected. No random seed, reproducibility control, or replicate-count parameter exists; each submission gives one random realization per input. The form checks mutations against the shortest total sequence length, but core code checks non-`N` length, so N-rich input can pass validation then fail.
- **Output:** FASTA-like downloadable text; headers record mutation count and Boolean flags; the browser highlights mutated positions.
- **Evidence:** [official Transmutation documentation](https://www.genomegeek.com/MPRA/documentation/#collapseThree); paper p. 1; repository [`forms.py` lines 340–377](https://github.com/hemberg-lab/MPRAnator/blob/master/iliasApp/forms.py#L340-L377), [`part3.py` lines 5–48](https://github.com/hemberg-lab/MPRAnator/blob/master/part3.py#L5-L48), and [`views.py` lines 150–226](https://github.com/hemberg-lab/MPRAnator/blob/master/iliasApp/views.py#L150-L226). A live reverse+complement test on 2026-08-14 returned the expected reverse complement.

#### 5. PWM-SeqGen motif sequence generation

- **What it does:** converts one or more nucleotide position-weight/frequency matrices into motif sequence collections in two modes:
  1. stochastic simulation according to per-position nucleotide probabilities; or
  2. exhaustive enumeration of k-mers, retaining those whose overall probability exceeds the user threshold.
- **Additional mode:** simulation output can keep duplicates or remove duplicate motifs. The result is FASTA motif sequences that can be pasted into MPRA Motifs, connecting probabilistic motif models to full oligo-library construction.
- **Interface/API entry point:** current web form [`/MPRA/PWM/`](https://www.genomegeek.com/MPRA/PWM/) and result route `/MPRA/PWM/Results/`. No API/downloadable client is advertised. PWM-SeqGen is documented in the paper and live documentation but is entirely absent from the public 2015 repository snapshot.
- **Input/output:** matrix header begins with `>`; four whitespace-separated numeric rows may contain integers or dot-decimal values. The docs/sample do not explicitly state nucleotide row order. Simulation headers include the source motif and simulation number. Exhaustive headers include the k-mer probability (`Prob`).
- **Restrictions:** required threshold 0–1 (default 0.1); required matrix text; simulations 1–1,000 (default 1); exhaustive mode is opt-in and simulation is default. Exhaustive enumeration necessarily grows as 4^k; no further documented length/output cap is shown.
- **Evidence:** [official PWM documentation](https://www.genomegeek.com/MPRA/documentation/#collapseFour); paper p. 2. Both modes and the two distinct header forms were verified against the live service on 2026-08-14.

#### 6. Ancillary BED coordinate-normalization script

- **What it claims to do:** the current official homepage advertises a downloadable Python script that converts original coordinates to equal-sized, centered coordinates with a user-selected range on each side. This is variant/background input preparation rather than sequence generation itself.
- **Interface/status:** homepage “Download Scripts” entry and POST `/MPRA/ScriptDownload/Bed/`; example-script-only/ancillary, not a documented core module or packaged API. No BED script exists in the public repository, and the live download returned HTTP 500 on 2026-08-14, so it is advertised but currently unavailable.
- **Evidence:** [official homepage](https://www.genomegeek.com/); repository file listing and `downloadScriptView` allowlist in [`views.py` lines 393–414](https://github.com/hemberg-lab/MPRAnator/blob/master/iliasApp/views.py#L393-L414).

#### 7. Programmatic access and example-code boundary

- **Motif and SNP:** the official homepage labels two downloadable Python files “API scripts.” They use `requests.post()` against the same result endpoints as the web forms, send form fields, request raw results with `usingDownload=True`, and save FASTA. They require the third-party `requests` package. They are modifiable examples, not a formal versioned REST schema.
- **Missing parameters:** the Motif example omits the documented `reverseComplement` field; the SNP example omits `makeSnpCombinations`. Those modes can only be used programmatically by manually adding the form field.
- **Broken nominal API route:** the repository separately declares `/API/MPRA/SNP`, but its view only returns the literal string `testing`; it is not a sequence-design API.
- **No equivalent client:** no API script is advertised for Transmutation or PWM-SeqGen.
- **Current script issues:** deployed examples still use `http://` although the site redirects to HTTPS, and the Python-3-style scripts write `result.content` bytes to a text-mode file, which raises a type error in Python 3. They therefore need modification even apart from server status.
- **Evidence:** [official homepage](https://www.genomegeek.com/); repository [`MpraMotifs_script.py`](https://github.com/hemberg-lab/MPRAnator/blob/master/downloadables/MpraMotifs_script.py), [`MpraSnps_script.py`](https://github.com/hemberg-lab/MPRAnator/blob/master/downloadables/MpraSnps_script.py), [`urls.py` lines 26–31](https://github.com/hemberg-lab/MPRAnator/blob/master/iliasApp/urls.py#L26-L31), and [`views.py` lines 419–424](https://github.com/hemberg-lab/MPRAnator/blob/master/iliasApp/views.py#L419-L424); paper p. 1 calls this a REST API using simple URLs.

### Version, release, license, installation, and maintenance

- **Current version/release date:** none is published. The bio.tools record has an empty `version` list. GitHub has no tags, releases, packages, or version declaration. The only public-source commit is `9969790d62410138d4281b7955da6d085f07b1bc`, authored and committed 2015-12-27. The paper was Advance Access on 2016-09-06 and appeared in the 2017-01-01 issue, but those are publication dates, not a numbered software release. Evidence: [bio.tools API record](https://bio.tools/api/tool/mpranator?format=json), [GitHub repository](https://github.com/hemberg-lab/MPRAnator), and paper p. 1.
- **License:** the authors' paper explicitly says the source is under the MIT license, and bio.tools records `MIT`. However, the GitHub snapshot contains no `LICENSE` file and GitHub detects no license. The best supported description is “declared MIT in the paper/registry, but the repository itself omits the license text,” not “no stated license” and not “a repository-embedded MIT license.”
- **How it is used/installed:** the intended route is the hosted, free/open-access web application; no installation is needed for that. Programmatic Motif/SNP use downloads example Python clients and requires `requests` (`pip install requests`). For self-hosting, the repository can be cloned, but it provides no installation instructions, `requirements.txt`, setup metadata, environment, container, or CI. Its one-line README is only `# MpraNator`. Source settings identify Django 1.8 and imports for `crispy_forms`, `djcelery`, `kombu`, and NumPy; widespread Python-2 constructs mean the snapshot is not Python-3-ready. The bio.tools registry calls it a web application and command-line tool on Linux/Windows/Mac but provides no downloads and no version.
- **Maintenance:** the **public repository is not actively maintained**: exactly one commit from 2015, no tags/releases, and no public update containing PWM-SeqGen or the BED helper. The hosted service is still reachable and has clearly been changed outside that repository (modernized pages, current PWM module, expanded limits, BED link), while bio.tools was last updated 2024-11-24. Operational checks on 2026-08-14 found the homepage, documentation, all forms, Transmutation results, and both PWM modes working, but the Motif and SNP result endpoints returned HTTP 500 for their own bundled sample inputs with valid CSRF sessions, and the BED-script download returned HTTP 500. Thus it is fair to call the public project/release stream inactive and the hosted service partially operational, not wholly dead and not demonstrably under active public development.

## Phase 2 findings

### A. FACTUALLY WRONG

1. **“the four live forms submit a JS-generated `ordering` field”** — Only the Motif and SNP oligo-assembly forms have the draggable component list and synthesize an `ordering` field. Transmutation and PWM Seq-Gen have neither that field nor that JavaScript, and their result views do not read it. Evidence: the four official forms ([Motif](https://www.genomegeek.com/MPRA/Motifs/), [SNP](https://www.genomegeek.com/MPRA/SNPs/), [Transmutation](https://www.genomegeek.com/MPRA/Transmutation/), [PWM](https://www.genomegeek.com/MPRA/PWM/)); repository [`part1.html` lines 81–118](https://github.com/hemberg-lab/MPRAnator/blob/master/iliasApp/templates/iliasApp/part1.html#L81-L118), [`mpraSnp.html` lines 80–112](https://github.com/hemberg-lab/MPRAnator/blob/master/iliasApp/templates/iliasApp/mpraSnp.html#L80-L112), and [`views.py` lines 34–44, 151–215, 325–342](https://github.com/hemberg-lab/MPRAnator/blob/master/iliasApp/views.py).

2. **“Headers are generated entirely by the tool; the user never supplies them.”** — MPRAnator generates descriptors, but it also preserves user-supplied names: Motif output embeds the background FASTA header, Transmutation prefixes the input FASTA name, SNP output begins with the supplied coordinate header, and PWM output uses the supplied PWM name. Evidence: [`oligo.py` lines 71–76](https://github.com/hemberg-lab/MPRAnator/blob/master/oligo.py#L71-L76), [`views.py` lines 210–211](https://github.com/hemberg-lab/MPRAnator/blob/master/iliasApp/views.py#L210-L211), and the official documentation’s Transmutation and PWM header examples ([documentation](https://www.genomegeek.com/MPRA/documentation/)).

3. **“`Part3Form` lacks the reverse/complement options the live site and Supplementary describe.”** — The public repository's `Part3Form` explicitly declares both `reverse` and `complement`, and its result view applies them. PWM code is absent from the snapshot, but reverse/complement Transmutation is not. Evidence: [`forms.py` lines 340–349](https://github.com/hemberg-lab/MPRAnator/blob/master/iliasApp/forms.py#L340-L349) and [`views.py` lines 164–194](https://github.com/hemberg-lab/MPRAnator/blob/master/iliasApp/views.py#L164-L194).

4. **“SNP module doubles as a plain assembly tool” and “can accept a set of FASTA sequences without a list of associated SNPs.”** — This is the paper-era/Supplementary statement quoted by the record, not a capability of the public software now available: the repository form explicitly raises `Enter SNPs!` when the SNP text is empty, and the current live form also rejects an empty SNP list. The record presents the older statement as an unqualified current capability instead of flagging the paper/software disagreement. Evidence: [`forms.py` lines 534–545](https://github.com/hemberg-lab/MPRAnator/blob/master/iliasApp/forms.py#L534-L545) and the [current SNP form](https://www.genomegeek.com/MPRA/SNPs/).

5. **“both [shipped REST scripts] 500 as distributed.”** — The exact currently served scripts do not receive an HTTP 500 when run as written. They POST to `http://www.genomegeek.com/...`; on 2026-08-14 that request followed a 301 to HTTPS, was converted to GET, then redirected to the input form and ended at HTTP 200. Under Python 3 the next line fails locally because `result.content` (bytes) is written to a text-mode file. Equivalent payloads posted directly to the HTTPS result URLs did return 500, so the underlying generators were failing, but the stated behavior and failure mechanism of the distributed clients are wrong. Evidence: the official homepage’s two API-script downloads ([homepage](https://www.genomegeek.com/)), the form endpoints, and the repository clients’ same text-mode write pattern ([Motif client lines 68–74](https://github.com/hemberg-lab/MPRAnator/blob/master/downloadables/MpraMotifs_script.py#L68-L74), [SNP client lines 58–64](https://github.com/hemberg-lab/MPRAnator/blob/master/downloadables/MpraSnps_script.py#L58-L64)).

6. **“IUPAC / degenerate-base awareness throughout the tool” and “motif and restriction-site matching are degenerate-code aware.”** — The support is narrower. The internal `regex_mapper` is used by the restriction-site collision matcher; Motif design substitutes motif strings and does not perform a degenerate-aware motif-matching operation. Moreover, the Transmutation alphabet/complement and mutation dictionaries omit `U`: a live `AUGC` input was rejected as “Invalid letters!” on 2026-08-14, despite the documentation saying “all nucleic acid IUPAC letters.” Thus ambiguity-code-aware Transmutation and restriction checking exist, but not awareness “throughout.” Evidence: [`myfunctions.py`](https://github.com/hemberg-lab/MPRAnator/blob/master/myfunctions.py), [`part3.py`](https://github.com/hemberg-lab/MPRAnator/blob/master/part3.py), [`oligo.py`](https://github.com/hemberg-lab/MPRAnator/blob/master/oligo.py), the [Transmutation form](https://www.genomegeek.com/MPRA/Transmutation/), and [official documentation](https://www.genomegeek.com/MPRA/documentation/).

7. **“indels ≤10 nt”** — Generated variants must have `abs(len(REF)-len(ALT)) < 10`; a 10-nt insertion/deletion difference is not generated. The form independently caps the ALT allele at length 10. Live checks on 2026-08-14 confirmed a 9-nt difference works while a 10-nt difference does not. Evidence: [`parseSNPs.py` lines 151–186](https://github.com/hemberg-lab/MPRAnator/blob/master/parseSNPs.py#L151-L186) and [`forms.py` lines 542–545](https://github.com/hemberg-lab/MPRAnator/blob/master/iliasApp/forms.py#L542-L545).

8. **“there is no object, no importable module”** — It is correct that there is no packaged or documented library API, but the absolute claim is false. The repository contains ordinary importable implementation modules (`part1`, `part3`, `oligo`, `mycustom`, `myfunctions`, `parseSNPs`) and defines `FastaFile`, `Sequence`, `SnpFile`, and related objects. They are internal and unsupported, not nonexistent. Evidence: repository root ([GitHub](https://github.com/hemberg-lab/MPRAnator)), [`mycustom.py` lines 16–73 and 124–195](https://github.com/hemberg-lab/MPRAnator/blob/master/mycustom.py), and [`part1.py`](https://github.com/hemberg-lab/MPRAnator/blob/master/part1.py).

9. **“The documented LABEL vocabulary on the live docs page is exhaustive (`<MOTIF>`, `BARCODE`, `RESTRICTION`, `ADAPTER`, `DUPLICATE_RESTRICTION_SITES`).”** — That list is only the Motif result vocabulary. The SNP section of the same official page additionally documents `<SNP>` and `<NUCLEOTIDE>` labels. This does not change the record's conclusion that MPRAnator lacks biological consequence annotation, but the factual claim of exhaustiveness is wrong. Evidence: [official documentation, Motif and SNP result sections](https://www.genomegeek.com/MPRA/documentation/).

### B. INCOMPLETE

1. **Repository Motif truncation.** The public result view silently uses only the first 20 background records and only the first 800 nt of each (`sequenceO[:20]`, `i.sequence[:800]`). The record discusses declared form caps but omits this much tighter implementation-only truncation; it is material because a seemingly accepted input can produce a library from only a subset of the supplied designs. Evidence: [`views.py` lines 81–84](https://github.com/hemberg-lab/MPRAnator/blob/master/iliasApp/views.py#L81-L84).

2. **Transmutation realization and reproducibility semantics.** The module emits one randomly shuffled/mutated realization per input sequence, provides neither a seed nor a replicate-count control, uses a simple mononucleotide shuffle, and applies combined operations in the fixed order scramble → reverse → complement → point mutation. The record names the four operations but does not convey these restrictions; they are material for determining whether negative-control libraries are reproducible or compositionally controlled. Evidence: [`part3.py` lines 5–48](https://github.com/hemberg-lab/MPRAnator/blob/master/part3.py#L5-L48) and [`views.py` lines 164–205](https://github.com/hemberg-lab/MPRAnator/blob/master/iliasApp/views.py#L164-L205).

3. **PWM input and run bounds.** The current PWM form constrains threshold to 0–1 and simulations to 1–1000, expects a `>` name followed by four whitespace-separated numeric rows, requires dot decimals, and exposes duplicate removal. The record explains the two modes and duplicate removal but omits the numeric bounds and complete accepted matrix syntax; these define the actual size and format of PWM-derived libraries. Evidence: [current PWM form](https://www.genomegeek.com/MPRA/PWM/) and [official PWM documentation](https://www.genomegeek.com/MPRA/documentation/).

4. **Example API clients do not expose all documented modes.** The downloadable Motif client omits `reverseComplement`, and the SNP client omits `makeSnpCombinations`; users must discover and add those form fields themselves. The record says programmatic access covers two modules but not that even those clients cover only a subset of their UI capabilities, which is material to the advertised programmatic interface. Evidence: [`MpraMotifs_script.py` data dictionary](https://github.com/hemberg-lab/MPRAnator/blob/master/downloadables/MpraMotifs_script.py#L45-L64), [`MpraSnps_script.py` data dictionary](https://github.com/hemberg-lab/MPRAnator/blob/master/downloadables/MpraSnps_script.py#L41-L55), and the [Motif](https://www.genomegeek.com/MPRA/Motifs/) and [SNP](https://www.genomegeek.com/MPRA/SNPs/) forms.

5. **Barcode filter/distance details.** The advertised edit-distance condition is not reliably enforced: the repository code counts *matching* positions, compares that number to `diffs`, retains the accumulated comparison list across candidates, and after a failed comparison regenerates without rechecking distance to existing barcodes. Its initial and fallback GC-bound predicates also differ, and barcoding is silently disabled unless the length, both GC bounds, and replicate count are all present. The record notes only that the distance test is “Hamming-style”; the omitted logic is material because neither the requested minimum separation nor consistent filtering is guaranteed by this snapshot. Evidence: [`part1.py` lines 52–88](https://github.com/hemberg-lab/MPRAnator/blob/master/part1.py#L52-L88) and [`getBarCodes` lines 295–319](https://github.com/hemberg-lab/MPRAnator/blob/master/part1.py#L295-L319).

6. **SNP parser and matching restrictions.** “VCF format” here means at least five whitespace-separated fields with no VCF-header handling, chromosomes limited to bare `1`–`22`/`X`/`Y`, and comma-separated ALT alleles; the supplied REF allele is not checked against the background. Background sequences with no matching in-range variant are omitted rather than passed through, and combination mode grows combinatorially without a SNP-count cap. The record mentions the human chromosome restriction and eager materialization but omits the other parser/output behaviors; they are material to knowing which variant sets are accepted and whether output faithfully represents all supplied backgrounds. Evidence: [`mycustom.py` lines 256–290](https://github.com/hemberg-lab/MPRAnator/blob/master/mycustom.py#L256-L290) and [`parseSNPs.py` lines 145–190](https://github.com/hemberg-lab/MPRAnator/blob/master/parseSNPs.py#L145-L190).

7. **Motif interval/reverse-complement edge cases in the public snapshot.** The form permits a zero substitution interval, but generation uses that value as a modulus divisor; the reverse-complement helper uses `[::1]` and therefore complements without reversing. The record relegates the latter to an “internal-only footnote” and does not report the zero-interval failure. Both are material because they change or prevent generated sequence libraries for documented controls. Evidence: [`oligo.py`](https://github.com/hemberg-lab/MPRAnator/blob/master/oligo.py), [`myfunctions.py` lines 18–25](https://github.com/hemberg-lab/MPRAnator/blob/master/myfunctions.py#L18-L25), and [`forms.py`](https://github.com/hemberg-lab/MPRAnator/blob/master/iliasApp/forms.py).

8. **Version/registry state.** The record reports zero GitHub tags/releases but never cleanly states that MPRAnator has no published current version or software release date; bio.tools' `version` list is empty. It also omits that bio.tools declares MIT, lists web/command-line interfaces and all three desktop platforms without a downloadable package, and was last updated 2024-11-24. This is material to reproducibility and to distinguishing a recently edited registry entry from an actual software release or active source maintenance. Evidence: [bio.tools API record](https://bio.tools/api/tool/mpranator?format=json) and [GitHub repository](https://github.com/hemberg-lab/MPRAnator).

### C. BALANCE

The record is broadly balanced. It gives unusually specific and substantial space to MPRAnator's real strengths—combinatorial motif placement, PWM sequence generation, modular oligo assembly, barcode replication, variant/indel handling, negative-control generation, structured FASTA provenance, collision warnings, and visual highlighting—while also documenting its packaging, maintenance, implementation, and live-service limitations. Limitations and outage observations are somewhat more granular and repeated in more sections than the capability discussion, but the strengths are still given proportionate space; the imbalance is not material.
