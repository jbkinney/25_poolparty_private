# Biopython fact-check

## Phase 1 inventory — frozen before reading the survey record

Frozen on 2026-08-14. This section records the independent yardstick assembled before opening `final/biopython.md`; it was not revised after Phase 2 began. “Documented API” means an importable public module/class/function covered by Biopython's Tutorial or generated API documentation. “Source-only” means code shipped under `Scripts/`, which the project's README calls miscellaneous standalone scripts, rather than an installed public API or console command.

The official 2009 application note describes the package as it existed then, not a frozen contract for the current API. In particular, its examples use `Bio.Alphabet`, and it describes local command wrappers and statistical-learning/population-simulation modules that have since been removed. Those differences are itemized below. Evidence for what the paper actually said is [Cock et al. (2009), pp. 1422–1423](../papers/Cock2009_biopython.pdf).

### Direct sequence construction and transformation

| Capability | API / interface and status | Stated restrictions or boundary | Primary evidence/location |
|---|---|---|---|
| Represent arbitrary nucleotide or protein strings | `Bio.Seq.Seq` (immutable), `Bio.Seq.MutableSeq` (mutable), and module-level functions; **documented API**. `Seq` also supports undefined (`Seq(None, length)`) and partially defined (`Seq({start: segment}, length)`) sequences and lazy providers. | Sequence data are ASCII. There is no current alphabet/type validation: a DNA-looking string and a protein-looking string can be concatenated, and biologically meaningless operations are not generally prevented. `Bio.Alphabet` was removed in 1.78. | [`Bio.Seq` API](https://biopython.org/docs/latest/api/Bio.Seq.html); [`Bio.Seq` source](https://github.com/biopython/biopython/blob/biopython-188/Bio/Seq.py); [sequence-object Tutorial](https://biopython.org/docs/latest/Tutorial/chapter_seq_objects.html); [`DEPRECATED.rst`, Bio.Alphabet](https://github.com/biopython/biopython/blob/biopython-188/DEPRECATED.rst) |
| Make substitutions, insertions, deletions, fragments, repeats, and concatenated constructs | `MutableSeq` item/slice assignment and deletion, `append`, `insert`, `pop`, `remove`, `extend`, `reverse`; `Seq`/`MutableSeq` slicing, `replace`, `join`, `+`, and `*`; **documented API**. These are sufficient primitives for user-written mutagenesis/enumeration loops. | Biopython supplies the primitives, not a mutation specification, saturation-mutagenesis engine, combinatorial variant enumerator, random-library generator, or dedicated library-design object. The caller must define and enumerate variants in ordinary Python. | [`Bio.Seq` API](https://biopython.org/docs/latest/api/Bio.Seq.html); [`Seq` and `MutableSeq` implementation](https://github.com/biopython/biopython/blob/biopython-188/Bio/Seq.py) |
| Complement, reverse complement, transcribe, back-transcribe, and translate | Methods on `Seq`/`MutableSeq` and `Bio.Seq.complement`, `reverse_complement`, `complement_rna`, `reverse_complement_rna`, `transcribe`, `back_transcribe`, `translate`; **documented API**. Mutable inputs can be changed with `inplace=True` for complement/reverse-complement operations. | “Back transcription” converts RNA to DNA; it is not protein-to-DNA reverse translation. Operations do not establish that input has the claimed molecule type. | [`Bio.Seq` API](https://biopython.org/docs/latest/api/Bio.Seq.html); [sequence-object Tutorial](https://biopython.org/docs/latest/Tutorial/chapter_seq_objects.html) |
| Translate and validate coding sequences under alternative genetic codes | `Seq.translate` / `Bio.Seq.translate` accept an NCBI table name, ID, or `CodonTable`, stop symbol, `to_stop`, `cds`, and gap; `Bio.SeqFeature.SeqFeature.translate` respects `codon_start` and `transl_table`; **documented API**. `cds=True` checks a valid start, complete codons, exactly one terminal stop, and no internal stop. | Ambiguous possible-stop codons translate to `X`; invalid codons raise; partial codons warn; dual-coding stop tables cannot be used with `to_stop=True`. Translation validates only the conditions selected, not expression or synthesis suitability. | [`Bio.Seq.translate`](https://biopython.org/docs/latest/api/Bio.Seq.html#Bio.Seq.translate); [`SeqFeature.translate`](https://biopython.org/docs/latest/api/Bio.SeqFeature.html#Bio.SeqFeature.SeqFeature.translate); [`Bio.Seq` source](https://github.com/biopython/biopython/blob/biopython-188/Bio/Seq.py) |
| Access genetic-code tables and a naive one-codon back table | `Bio.Data.CodonTable` exposes standard, non-standard, DNA, RNA, generic, and ambiguous NCBI tables; tables include forward mappings, starts/stops, and a `back_table`; `make_back_table` constructs one; **documented API**. | A back table deliberately selects a single codon per amino acid (by sorted order); it is not organism-aware, probabilistic, degenerate, or an enumerator of synonymous libraries. | [`Bio.Data.CodonTable` API](https://biopython.org/docs/latest/api/Bio.Data.CodonTable.html); [source](https://github.com/biopython/biopython/blob/biopython-188/Bio/Data/CodonTable.py) |
| Learn codon preferences, calculate CAI, and emit a codon-optimized DNA sequence | `Bio.SeqUtils.CodonAdaptationIndex(reference_coding_sequences, table=...)`, `.calculate(sequence)`, and `.optimize(sequence, seq_type="DNA"|"RNA"|"protein", strict=...)`; **documented API**. Protein input is genuine reverse translation to DNA. | Optimization uses **only one maximally preferred codon per amino acid**. With `strict=True`, tied preferred codons raise; non-strict mode selects one. It returns one bare `Seq`, not a library, and does not optimize GC, repeats, motifs, restriction sites, synthesis constraints, or multiple objectives. References must be valid unambiguous coding triplets; absent codons receive a 0.5 pseudocount. | [`CodonAdaptationIndex` API](https://biopython.org/docs/latest/api/Bio.SeqUtils.html#Bio.SeqUtils.CodonAdaptationIndex); [1.88 implementation](https://github.com/biopython/biopython/blob/biopython-188/Bio/SeqUtils/__init__.py) |
| Find exact or ambiguity-aware subsequences | `Seq.search(subsections)` searches many exact subsequences in one pass; `Bio.SeqUtils.nt_search(seq, subseq)` interprets IUPAC ambiguity codes in the query; **documented API**. These can screen candidate collections for forbidden/required motifs. | `Seq.search` is exact string matching. `nt_search` scans the forward strand; callers must handle the reverse complement and library-level filtering themselves. Neither function designs replacements. | [`Seq.search` API](https://biopython.org/docs/latest/api/Bio.Seq.html#Bio.Seq.Seq.search); [`nt_search` API/source](https://github.com/biopython/biopython/blob/biopython-188/Bio/SeqUtils/__init__.py) |

### Explicit current-scope boundaries and changes since the 2009 paper

The current documented/source inventory exposes **no dedicated API or CLI for random sequence generation, exhaustive/combinatorial mutation enumeration, degenerate-oligo expansion, barcode design, pooled-library balancing, primer selection, DNA assembly planning, synthesis-constraint repair, multiobjective sequence optimization, or protein design/folding**. Users can implement such workflows with ordinary Python and the `Seq`/`MutableSeq`/`SeqRecord`/`SeqIO` primitives, and can evaluate several relevant constraints with the modules above, but that does not make those algorithms Biopython capabilities.

Several statements accurate in the 2009 paper are no longer accurate descriptions of 1.88:

- `Seq` no longer has an `Alphabet`; `Bio.Alphabet` was removed in 1.78.
- `Bio.Application` and its local BLAST, ClustalW, EMBOSS, and other command-line wrappers were removed in 1.86. Remote `Bio.Blast.qblast`, format parsers, and the EMBOSS Primer3/PrimerSearch parsers remain.
- `Bio.Motif` was replaced by `Bio.motifs`; old AlignACE/CompareACE command wrappers disappeared, and current core does not perform de-novo motif discovery.
- The supervised-learning modules `Bio.kNN`, `Bio.LogisticRegression`, `Bio.NaiveBayes`, `Bio.MaxEntropy`, Markov-model code, and substantive `Bio.HMM` submodules were removed in 1.86. `Bio.Cluster` remains.
- `Bio.PopGen.FDist` and `Bio.PopGen.SimCoal` were removed in 1.70; `Bio.PopGen.GenePop` parsing/manipulation remains, not the paper's wrappers/simulation suite.
- The paper's table lists EMBL as read-only; current `Bio.SeqIO` reads **and writes** EMBL.
- `Bio.Align.AlignInfo.SummaryInfo.dumb_consensus` and `gap_consensus` were removed in 1.86; current consensus-like functionality includes motif count consensuses rather than those methods.

Primary evidence: [Cock et al. 2009, pp. 1422–1423](../papers/Cock2009_biopython.pdf); [1.88 `DEPRECATED.rst`](https://github.com/biopython/biopython/blob/biopython-188/DEPRECATED.rst); [current `Bio.SeqIO` registry](https://github.com/biopython/biopython/blob/biopython-188/Bio/SeqIO/__init__.py).

## Phase 2 findings

### A. FACTUALLY WRONG

1. **Wrong introduction version for undefined sequences.** The record says, **“Since 1.78 it also supports undefined and partially-defined sequences.”** Undefined `Seq(None, length=...)` support was introduced in **1.79**, not 1.78; the 1.79 release notes explicitly call it new. The current capability is real, but its version history is wrong. [1.88 `NEWS.rst`, 1.79 section](https://github.com/biopython/biopython/blob/biopython-188/NEWS.rst); [`Bio.Seq` API](https://biopython.org/docs/latest/api/Bio.Seq.html).

2. **`Alignment` and `SeqIO.to_dict()` are mischaracterized.** The record calls `Alignment`/`Alignments`/`MultipleSeqAlignment` **“alignments, i.e. equal-length gapped rows”** and groups **“`SeqIO.to_dict()` / `index()` / `index_db()` [as] views over a file.”** Only the legacy `MultipleSeqAlignment` directly stores equal-length gapped `SeqRecord` rows; modern `Alignment` stores original sequences (which can differ in length) plus a coordinate array, and `Alignments` is a container of such objects. Separately, `to_dict()` eagerly consumes any record iterable into an ordinary in-memory dictionary; only `index()` and `index_db()` are file-backed random-access objects. [`Bio.Align.Alignment` / `Alignments` source](https://github.com/biopython/biopython/blob/biopython-188/Bio/Align/__init__.py); [`Bio.SeqIO.to_dict`, `index`, and `index_db`](https://biopython.org/docs/latest/api/Bio.SeqIO.html).

3. **Insertion does not preserve every feature.** The record says, **“Insertion is `rec[:i] + insert + rec[i:]` with features maintained.”** `SeqRecord` slicing retains and shifts only features fully contained in each slice; a feature that crosses `i` is omitted from both slices and therefore lost after concatenation. Most general annotations and `dbxrefs` are also discarded by each slice. [`SeqRecord.__getitem__` and `__add__`](https://github.com/biopython/biopython/blob/biopython-188/Bio/SeqRecord.py); [`Bio.SeqRecord` API](https://biopython.org/docs/latest/api/Bio.SeqRecord.html).

4. **Arbitrary record metadata do not all round-trip through GenBank.** The record says the `annotations`, `features`, and `letter_annotations` containers **“all round-trip to GenBank.”** GenBank writing maps only supported INSDC record fields and features/qualifiers; arbitrary `annotations` keys and general `letter_annotations` (for example per-letter quality or custom arrays) are not serialized and therefore cannot generally round-trip. [`Bio.SeqIO.InsdcIO` GenBank writer](https://github.com/biopython/biopython/blob/biopython-188/Bio/SeqIO/InsdcIO.py); [`SeqRecord.letter_annotations`](https://biopython.org/docs/latest/api/Bio.SeqRecord.html#Bio.SeqRecord.SeqRecord.letter_annotations).

5. **The current statistical-learning inventory is obsolete.** The record says, **“Biopython's only ML/statistical content is the legacy `Bio.HMM`, `Bio.Cluster`, and `Bio.PopGen`.”** Current 1.88 has no substantive HMM implementation: `Bio.HMM.DynamicProgramming`, `Trainer`, `MarkovModel`, and `Utilities`, along with `Bio.kNN`, `Bio.LogisticRegression`, `Bio.NaiveBayes`, and `Bio.MaxEntropy`, were removed in 1.86; only an empty `Bio.HMM` package initializer remains. `Bio.Cluster` remains, while current `Bio.PopGen` contains GenePop parsing/manipulation rather than the 2009 simulation/outlier suite. [1.88 `DEPRECATED.rst`, statistical modules](https://github.com/biopython/biopython/blob/biopython-188/DEPRECATED.rst); [`Bio.HMM` source](https://github.com/biopython/biopython/tree/biopython-188/Bio/HMM); [`Bio.PopGen` source](https://github.com/biopython/biopython/tree/biopython-188/Bio/PopGen).

6. **Two 2009-to-current removals are left unflagged and the package-directory list obscures them.** The record reproduces a current package list containing **“Alphabet … HMM … PopGen”** and later lists **“population genetics (`Bio.PopGen`)”** without explaining that `Bio.Alphabet` is now only an import-failing compatibility stub, or that the paper's `Bio.PopGen.FDist` and `Bio.PopGen.SimCoal` functionality was removed in 1.70. The correct current picture is no Alphabet object and only GenePop under `Bio.PopGen`; the paper's Alphabet, coalescent simulation, and FST-outlier claims are historical. [`Bio.Alphabet` stub](https://github.com/biopython/biopython/blob/biopython-188/Bio/Alphabet/__init__.py); [1.88 `DEPRECATED.rst`](https://github.com/biopython/biopython/blob/biopython-188/DEPRECATED.rst); [Cock et al. 2009, pp. 1422–1423](../papers/Cock2009_biopython.pdf).

7. **The transcript-format claim conflates formats with different fields.** The record says **“BED12/bigBed/PSL/bigPsl exon-block transcript models with `thickStart`/`thickEnd` CDS bounds are read and written”** and later that **“The same exon-block model is read and written for `psl`, `bigpsl`, `bigbed`, `bigmaf`.”** BED12/bigBed and bigPsl carry BED `thickStart`/`thickEnd`; ordinary PSL has block coordinates but no `thickStart`/`thickEnd` fields, while bigMaf is BED3 plus a MAF block and is a multiple-alignment container, not that BED12 transcript/CDS model. [`Bio.Align.bed`](https://github.com/biopython/biopython/blob/biopython-188/Bio/Align/bed.py); [`Bio.Align.psl`](https://github.com/biopython/biopython/blob/biopython-188/Bio/Align/psl.py); [`Bio.Align.bigpsl` declaration](https://github.com/biopython/biopython/blob/biopython-188/Bio/Align/bigpsl.py); [`Bio.Align.bigmaf` BED3+MAF declaration](https://github.com/biopython/biopython/blob/biopython-188/Bio/Align/bigmaf.py).

8. **`CodonAligner` is misattributed split-codon functionality.** The record calls BED/PSL plus `Bio.Align.CodonAligner` **“A second route to the same arithmetic”** as extracting and translating a CDS whose codon spans exons. `CodonAligner` aligns a protein to a nucleotide sequence while allowing frameshifts; it does not interpret BED/PSL exon models, remove introns, or map an edit across an exon-spanning codon. Joined feature extraction is supplied by `SeqFeature`/`CompoundLocation`; codon-aware protein–nucleotide alignment is a separate capability. [`CodonAligner` API](https://biopython.org/docs/latest/api/Bio.Align.html#Bio.Align.CodonAligner); [`SeqFeature.extract` / `translate`](https://biopython.org/docs/latest/api/Bio.SeqFeature.html).

9. **Not every `Bio.Align.formats` entry is writable.** The record claims **“Modern `Bio.Align` genomic file I/O — read *and write* for the full `formats` tuple”** and lists all 20 formats. In 1.88, `emboss`, `hhr`, `msf`, and `tabular` expose readers but no `AlignmentWriter`; passing them to `Bio.Align.write` is not supported. [`Bio.Align` format dispatch](https://github.com/biopython/biopython/blob/biopython-188/Bio/Align/__init__.py); [`emboss`](https://github.com/biopython/biopython/blob/biopython-188/Bio/Align/emboss.py), [`hhr`](https://github.com/biopython/biopython/blob/biopython-188/Bio/Align/hhr.py), [`msf`](https://github.com/biopython/biopython/blob/biopython-188/Bio/Align/msf.py), and [`tabular`](https://github.com/biopython/biopython/blob/biopython-188/Bio/Align/tabular.py) implementations.

10. **The `Bio.SeqIO` read/write list includes read-only formats.** The record says **“~30 `Bio.SeqIO` formats read/write (… SnapGene, GCK, … GFA1/2, `twobit`, …).”** SnapGene, GCK, GFA1/GFA2, and twoBit are read-only in `SeqIO` 1.88 (as are several other registered inputs); the reader and writer registries are deliberately asymmetric. [`Bio.SeqIO` format table and registries](https://github.com/biopython/biopython/blob/biopython-188/Bio/SeqIO/__init__.py).

11. **The linked “latest” documentation was not 1.88 at the audit date.** The sources table labels `https://biopython.org/docs/latest/Tutorial/index.html` **“Tutorial & Cookbook, 1.88,”** but the project's documentation landing page still identified the published latest documentation as **1.87** on 2026-08-14, consistent with the record's later admission that the website lagged the release. The package itself is 1.88; this is a documentation-version error, not a package-version error. [Biopython documentation landing page](https://biopython.org/wiki/Documentation); [PyPI 1.88 release metadata](https://pypi.org/project/biopython/).

### B. INCOMPLETE

1. **Complete sequence-editing and transformation primitives.** The record reduces `MutableSeq` largely to per-position assignment and `SeqRecord` arithmetic, omitting slice assignment/deletion, `insert`, `append`, `extend`, `pop`, `remove`, `replace`, `join`, repetition, RNA complements, back-transcription, and in-place complement/reverse-complement modes. It also omits the important restriction that current `Seq` has no molecule/alphabet validation and will accept biologically nonsensical DNA/protein combinations. [`Bio.Seq` API](https://biopython.org/docs/latest/api/Bio.Seq.html); [sequence-object Tutorial](https://biopython.org/docs/latest/Tutorial/chapter_seq_objects.html). This is material because these are the actual building blocks from which a user can construct variant sets, and the lack of type checking is a correctness hazard.

2. **CDS validation and genetic-code/back-table APIs.** `Seq.translate(..., cds=True)` validates a start, complete codons, one terminal stop, and no internal stops; translation accepts named/numbered/custom NCBI tables, and `SeqFeature.translate` honors `codon_start`/`transl_table`. `Bio.Data.CodonTable` also exposes DNA/RNA/ambiguous alternative codes and a deliberately naive one-codon `back_table`/`make_back_table`. [`Bio.Seq.translate`](https://biopython.org/docs/latest/api/Bio.Seq.html#Bio.Seq.translate); [`Bio.SeqFeature.translate`](https://biopython.org/docs/latest/api/Bio.SeqFeature.html#Bio.SeqFeature.SeqFeature.translate); [`Bio.Data.CodonTable`](https://biopython.org/docs/latest/api/Bio.Data.CodonTable.html). This is material because it separates coding-sequence validation and basic reverse translation from the CAI optimizer the record does discuss.

3. **Multi-pattern and ambiguity-aware motif screening.** `Seq.search` searches many exact subsequences in one pass, while `Bio.SeqUtils.nt_search` interprets IUPAC ambiguity in the query (forward strand only). [`Seq.search`](https://biopython.org/docs/latest/api/Bio.Seq.html#Bio.Seq.Seq.search); [`nt_search`](https://biopython.org/docs/latest/api/Bio.SeqUtils.html#Bio.SeqUtils.nt_search). This is material because forbidden/required motif screening is a direct library-filtering primitive, and its strand/ambiguity limits affect correct use.

4. **Sequence-quality and read-collection modes.** The record names FASTQ cookbook recipes but does not document per-letter qualities or the ABI, `abi-trim` (Mott trimming), PHD, ACE, SFF, FASTQ, and QUAL interfaces in `Bio.SeqIO`/`Bio.Sequencing`. [`Bio.SeqIO` format table](https://biopython.org/docs/latest/api/Bio.SeqIO.html); [`Bio.Sequencing` API](https://biopython.org/docs/latest/api/Bio.Sequencing.html). This is material for validating or processing physically synthesized/assayed sequence collections.

5. **Alignment-collection manipulation beyond coordinate liftover.** The record gives extensive space to file formats and liftover but omits `Alignment` row/column slicing, concatenation, sorting, reverse complement, frequencies, substitution counts/matrices, coordinate indices/inverse indices, counts, and `Alignment.from_alignments_with_same_reference`. [`Bio.Align` API](https://biopython.org/docs/latest/api/Bio.Align.html). These are material operations for comparing, consolidating, and quality-checking variant collections.

6. **Experimental codon-alignment builder and its stability restriction.** `Bio.codonalign.build` constructs a codon alignment from a protein MSA and corresponding nucleotide records, but the whole module raises `BiopythonExperimentalWarning` and may change. [`Bio.codonalign` source/API](https://github.com/biopython/biopython/blob/biopython-188/Bio/codonalign/__init__.py); [experimental-code policy](https://pypi.org/project/biopython/). This is material because it is a collection-construction mode distinct from `CodonAligner`, and its experimental status affects reliance on it.

7. **CAPS variant discrimination.** The record only parenthetically calls `Bio.CAPS` “restriction-site polymorphism detection.” `CAPSMap(alignment, enzymes).dcuts` reports each differential site's position, enzyme, sequences cut, and sequences blocked, requires equal-length aligned variants, and does not design the primers implied by a CAPS assay. [`Bio.CAPS` API](https://biopython.org/docs/latest/api/Bio.CAPS.html). This is material because it directly discriminates members of a sequence-variant set using restriction enzymes.

8. **Current GenePop collection operations.** Beyond a generic `Bio.PopGen` name, current 1.88 can parse and reconstruct GenePop allele collections, stream very large files, split records by population or locus, and remove populations/loci; population names are documented as unreliable and streaming is one-pass. [`Bio.PopGen.GenePop` source](https://github.com/biopython/biopython/tree/biopython-188/Bio/PopGen/GenePop). This is material because it is the actual current variant/genotype collection support left after the paper's FDist/SimCoal modules disappeared.

9. **Bootstrap collection generation.** `Bio.Phylo.Consensus.bootstrap`, `bootstrap_trees`, `bootstrap_consensus`, and `Bio.Nexus.Nexus.bootstrap` generate column-resampled alignment/tree collections; `Bio.Phylo.Consensus.bootstrap` is marked obsolete. [`Bio.Phylo.Consensus`](https://github.com/biopython/biopython/blob/biopython-188/Bio/Phylo/Consensus.py); [`Bio.Nexus.Nexus`](https://github.com/biopython/biopython/blob/biopython-188/Bio/Nexus/Nexus.py). This is material—even if niche—because it is an actual collection-generation mode, albeit statistical resampling rather than designed biological variants.

10. **Motif consensus/scanning modes and restrictions.** The record's claim to give the “complete documented surface” omits `counts.calculate_consensus` identity/case controls, pseudocount/background handling, PWM/PSSM score distributions, false-positive/false-negative/balanced/Patser thresholds, motif comparison, and several read/write formats. It also does not state that instances must be equal-length, PSSM calculation is DNA-specific, substitution-matrix consensus is unimplemented, and `degenerate_consensus` returns one IUPAC-compressed sequence rather than enumerating it. [motif Tutorial](https://biopython.org/docs/latest/Tutorial/chapter_motifs.html); [`Bio.motifs.matrix`](https://biopython.org/docs/latest/api/Bio.motifs.matrix.html). This is material because these controls determine how candidate libraries can be screened and clarify that a degenerate consensus is not a generated library.

11. **Restriction digest, topology, and cloning-screen modes.** The record mentions site analysis and a few filters but omits enzyme/Batch `.search(linear=True|False)`, `.catalyse`/`.catalyze`, circular-boundary cuts, 5′/3′/blunt overhang classification, compatible ends, iso/equi/neoschizomers, suppliers, and `Analysis` filters by site count and region. It also omits that the bundled database is REBASE release 404 (2024), enzymes with unknown cut positions cannot be digested, and the model does not perform ligation/assembly design or infer sample methylation. [`Bio.Restriction` API](https://biopython.org/docs/latest/api/Bio.Restriction.html); [1.88 restriction source/data](https://github.com/biopython/biopython/tree/biopython-188/Bio/Restriction). This is material because these modes make the module substantially more useful for construct screening than “unwanted-site checking,” while setting its laboratory limits.

12. **Melting-temperature models and caller-supplied context.** `Tm_Wallace`, `Tm_GC`, and `Tm_NN` cover DNA/DNA, DNA/RNA, and RNA/RNA nearest-neighbor tables, salt, ion/dNTP, DMSO/formamide, mismatches/dangling ends, self-complementarity, and custom thermodynamic tables. They do not automatically align an oligo to its target or detect self-complementarity/mismatches/loops; the caller must provide `c_seq`, `shift`, and `selfcomp` when needed. [`Bio.SeqUtils.MeltingTemp` API](https://biopython.org/docs/latest/api/Bio.SeqUtils.MeltingTemp.html). This is material because the record's phrase “scores a Tm” hides both a substantial screening capability and the conditions needed for a valid result.

13. **Detailed DNA/protein candidate descriptors.** The one-line “protein physicochemistry” mention misses `ProteinAnalysis` amino-acid composition, molecular weight, aromaticity, instability, flexibility, GRAVY/custom scales, pI/charge, extinction coefficient, and coarse secondary-structure fraction, plus local composition complexity. The record likewise does not explain GC ambiguity policies, `GC123`/GC skew, molecular-weight topology/strand/monoisotopic modes, or their input restrictions. [`Bio.SeqUtils` API](https://biopython.org/docs/latest/api/Bio.SeqUtils.html); [`ProteinAnalysis`](https://biopython.org/docs/latest/api/Bio.SeqUtils.ProtParam.html); [`lcc`](https://biopython.org/docs/latest/api/Bio.SeqUtils.lcc.html). This is material because these are the package's main built-in physicochemical filters for designed candidates, although they are not optimization algorithms.

14. **Protein-sequence-to-coordinate construction.** `Bio.PDB.PICIO.read_PIC_seq(seq_record)` creates a `Structure` with default internal coordinates from a standard protein sequence, and `Bio.PDB.internal_coords` can edit dihedrals/bond geometry and rebuild atom coordinates. It is explicitly an idealized/default-coordinate construction, not folding or structure prediction, and degrades rapidly away from known geometry. [`Bio.PDB.PICIO`](https://biopython.org/docs/latest/api/Bio.PDB.PICIO.html); [`Bio.PDB.internal_coords`](https://biopython.org/docs/latest/api/Bio.PDB.internal_coords.html). This is material as an obscure but real way to generate structural representations for designed protein sequences, with a crucial limitation the generic “3D structure” line does not convey.

15. **Explicit remote design-screening entry points.** The record lists remote database clients but omits `Bio.Blast.qblast` for remote similarity searches and `Bio.ExPASy.ScanProsite.scan` for remote PROSITE screening, while `Bio.SearchIO` parses results from separately run BLAST/HMMER/Infernal/Exonerate/InterProScan tools. [`Bio.Blast` API](https://biopython.org/docs/latest/api/Bio.Blast.html); [`ScanProsite` API](https://biopython.org/docs/latest/api/Bio.ExPASy.ScanProsite.html); [`Bio.SearchIO` API](https://biopython.org/docs/latest/api/Bio.SearchIO.html). This is material because these are concrete candidate novelty/domain-screening interfaces, but their network/external-tool dependencies distinguish them from in-process design.

### C. BALANCE

The record correctly and repeatedly establishes that Biopython has no dedicated library-design layer, and it gives exceptional space to modern genomic-coordinate and alignment-format strengths. Overall, however, it is **not balanced for the requested design/library scope**: limitations and absent domain-specific workflows are documented far more deeply and repetitively than the package's many usable construction, screening, collection, and validation primitives. Core editing modes, CDS validation, motif thresholds, restriction digests, CAPS, GenePop, thermodynamic models, protein/DNA descriptors, experimental codon-alignment construction, bootstrap generation, and PIC protein-coordinate construction are missing or compressed into name-only lists. The result fairly rejects Biopython as a turnkey library designer but materially understates what current Biopython can do as infrastructure for building and checking sequence collections.
