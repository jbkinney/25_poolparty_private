### Capability records

1. **Normalize several dense sequence representations.** `sp.cast_seqs` accepts a string/bytes scalar, nested lists/sequences of them, and NumPy Unicode/object/bytes arrays and converts them to ASCII `|S1`; a `uint8` array (the package's OHE representation) passes through. `NestedStr`, `StrSeqType`, and `SeqType` expose the accepted types. **Exposure:** `cast_seqs` and the type aliases are in the documented root API (the docs have a Types page), while the README describes the formats. **Restrictions:** plain empty strings are rejected; conversion is ASCII; unequal-length collections require either the padding behavior of NumPy fixed-width strings or `Ragged`. Evidence: [`_utils.py` lines 8–72](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/_utils.py#L8-L72), [README lines 10–14](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/README.md#L10-L14).

2. **Built-in and custom alphabets.** `sp.DNA` is ACGT, `sp.RNA` is ACGU, and `sp.AA` maps the standard DNA codon table to the 20 standard amino-acid symbols plus `*`; `sp.NucleotideAlphabet` and `sp.AminoAlphabet` construct custom mappings. Alphabet objects expose OHE/decode; nucleotide alphabets expose reverse complement; amino alphabets expose translation. **Exposure:** documented API and quick-start table. **Restrictions:** a nucleotide alphabet and its complement must contain no repeats, and the complement string must literally be the reverse of the alphabet string; an amino alphabet requires equal numbers of same-length codons and single-character output symbols. The built-in AA table contains `T`, not `U`: `sp.AA.translate` therefore treats ordinary RNA codons containing `U` as unknown unless the caller builds a custom RNA-based `AminoAlphabet`, despite the README's “DNA/RNA → amino acids” caption. Evidence: [`_alphabets.py` lines 25–94](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/alphabets/_alphabets.py#L25-L94), [`_alphabets.py` lines 297–361](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/alphabets/_alphabets.py#L297-L361), and the built-ins in [`alphabets/__init__.py` lines 3–73](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/alphabets/__init__.py#L3-L73).

3. **Generate uniform random nucleotide collections.** `sp.random_seqs(shape, alphabet, seed)` independently samples symbols from a `NucleotideAlphabet` with NumPy's RNG and returns an `S1` array of exactly the requested shape. It accepts an integer seed, a NumPy `Generator`, or no seed. **Exposure:** documented root API and quick-start example. **Restrictions:** this is uniform independent sampling only; it has no GC, motif, edit-distance, uniqueness, codon, synthesis, or other design constraints, and its public signature is nucleotide-alphabet-only (there is no built-in protein random generator). Evidence: [`_modifiers.py` lines 281–304](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/_modifiers.py#L281-L304), [README lines 24–30](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/README.md#L24-L30).

4. **Generate composition-matched controls by k-let-preserving shuffle.** `sp.k_shuffle(seqs, k, alphabet, *, length_axis, ohe_axis, seed)` rearranges each input while preserving its exact k-let counts. It accepts dense strings/bytes and OHE, supports custom `NucleotideAlphabet` instances, runs the graph algorithm in Rust, and returns the same representation class (bytes or OHE). A fixed integer seed is reproducible across runs/thread counts and derives independent per-row shuffles; changing the batch size changes per-row seeds. **Exposure:** documented root API and quick-start example. **Restrictions:** `alphabet` is actually a required positional argument even though the quick-start call omits it and would raise `TypeError`; array inputs need `length_axis`, OHE also needs `ohe_axis`; `k` must be positive, and the Rust implementation returns the sequence unchanged when `k >= sequence length`; no `Ragged` overload and no built-in `AminoAlphabet` overload exist. Evidence: [`_modifiers.py` lines 39–108](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/_modifiers.py#L39-L108), [`kshuffle.rs` lines 135–203](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/src/kshuffle.rs#L135-L203), and the broken omission in [README line 48](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/README.md#L48).

5. **Reverse-complement nucleotide sequences.** `sp.reverse_complement(seqs, alphabet, length_axis=None, ohe_axis=None)` and `sp.DNA.reverse_complement(...)` / `sp.RNA.reverse_complement(...)` operate on dense strings, byte arrays, or OHE; the alphabet-object method additionally accepts `out=` for a preallocated result. Non-alphabet bytes pass through the byte translation table unchanged. **Exposure:** documented API and quick-start example. **Restrictions:** only nucleotide alphabets; S1 arrays need an explicit length axis and OHE needs both axes; the root wrapper does not expose `out=`. Evidence: [`_modifiers.py` lines 14–36](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/_modifiers.py#L14-L36) and [`_alphabets.py` lines 149–235](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/alphabets/_alphabets.py#L149-L235).

6. **Reverse-complement selected variable-length rows.** `sp.rag.reverse_complement(rag, comp_lut, *, mask=None, copy=True)` handles an S1 `Ragged`, optionally only rows selected by a Boolean mask and optionally mutating the data buffer with `copy=False`; it preserves/reuses offsets. **Exposure:** publicly exported by `seqpro.rag` in source, but omitted from the explicit member list on the rendered Ragged API page and absent from the quick start. **Restrictions:** exactly a char/S1 Ragged with no fixed trailing dimensions; caller supplies a 256-entry `uint8` complement LUT; mask length must equal row count; in-place mode is safe only for owned data. Evidence: [`rag/__init__.py` lines 3–29](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/rag/__init__.py#L3-L29), [`rag/_ops.py` lines 22–100](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/rag/_ops.py#L22-L100), versus [`docs/api/ragged.md`](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/docs/api/ragged.md).

7. **Randomly crop/jitter aligned sequence and assay arrays.** `sp.jitter(*arrays, max_jitter, length_axis, jitter_axes, seed)` draws crop starts independently over designated sample axes and applies the same starts to every supplied array, allowing a sequence and aligned tracks to stay synchronized. Output length is `L - 2*max_jitter`. **Exposure:** documented root API; a quick-start example exists. **Restrictions:** NumPy arrays only; arrays must have matching selected-axis sizes and must remain positive length; `jitter_axes` is required by the actual API although the quick-start example omits it and is invalid. Evidence: [`_modifiers.py` lines 144–207](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/_modifiers.py#L144-L207), [README lines 54–55](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/README.md#L54-L55).

8. **Pad or truncate dense sequence batches.** `sp.pad_seqs(seqs, pad={'left','right','both'}, pad_value, length, length_axis)` coerces string collections to a fixed width or changes byte/OHE arrays to an explicit width. Both-sided odd padding/truncation puts the extra change on the right; OHE padding is all-zero. **Exposure:** documented API and quick-start example. **Restrictions:** plain string input needs a one-character `pad_value`; byte/OHE arrays need explicit `length` and `length_axis`; this function does not accept `Ragged` (which has separate padding APIs). Evidence: [`_encoders.py` lines 24–122](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/_encoders.py#L24-L122).

9. **One-hot encode/decode DNA, RNA, or protein collections.** `sp.ohe` / `sp.decode_ohe` and `alphabet.ohe` / `alphabet.decode_ohe` operate on dense and `Ragged` S1 collections. Dense encoding appends an alphabet axis; Ragged encoding yields `(n, None, alphabet_size, ...)` and keeps offsets. Characters outside the alphabet encode as an all-zero row; decoding an all-zero row uses `unknown_char` (`N` by default at module level/nucleotides and `X` for `sp.AA.decode_ohe`). **Exposure:** documented API, quick-start examples for DNA and amino acids, and Ragged tutorial examples. **Restrictions:** only S1 Ragged inputs and `uint8` Ragged OHE; Ragged decode ignores the supplied `ohe_axis` and assumes its canonical axis; multi-hot input is not rejected by ordinary decode. Evidence: [`_encoders.py` lines 125–228](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/_encoders.py#L125-L228), [README lines 34–36 and 64–66](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/README.md#L34-L66).

10. **Tokenize/detokenize with arbitrary character-to-integer maps.** `sp.tokenize`, `sp.decode_tokens`, and corresponding nucleotide-alphabet methods map characters to `int32` IDs and back, with explicit unknown token/character policies. Dense tokenization accepts an `int32 out=` buffer; dense and Ragged paths can force/disable the parallel LUT kernel. **Exposure:** documented API and quick-start example; the alphabet-object delegates are visible through the alphabet API. **Restrictions:** ASCII single-character keys, `int32` output, S1 Ragged input / `int32` Ragged decode; `out=` is dense-only and forcing parallel with a strided `out` errors. Evidence: [`_encoders.py` lines 231–376](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/_encoders.py#L231-L376), [`_alphabets.py` lines 96–147](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/alphabets/_alphabets.py#L96-L147).

11. **Translate nucleotide collections to amino-acid collections.** `sp.AA.translate` (or a custom `AminoAlphabet.translate`) supports dense strings/bytes, variable-length S1 `Ragged`, and OHE `Ragged`; OHE input yields OHE amino acids. It is case-insensitive. `unknown=` accepts one ASCII marker (default `X`) or `"drop"`; drop removes noncanonical codons and returns a Ragged even from dense input. `validate=True` instead fails on nonalphabet bytes or non-one-hot rows. `truncate_stop=True` retains the first stop and removes everything after it. Custom codon mappings and non-three-base codons use a generic translation path. **Exposure:** `AminoAlphabet` is in the documented API; basic translation is in the quick start; Ragged bytes/OHE and stop truncation are demonstrated in the Ragged guide; the `unknown` and validation modes are in the generated method documentation, not quick-start examples. **Restrictions:** every sequence length must be divisible by the codon width; OHE is supported only as Ragged and requires `nuc_alphabet`; stop truncation is Ragged-only; `unknown='drop'` is not supported for Ragged inputs with fixed trailing/multitrack dimensions; the built-in table is DNA (`T`) rather than RNA (`U`). Evidence: [`_alphabets.py` lines 464–525](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/alphabets/_alphabets.py#L464-L525), [`_alphabets.py` lines 580–726](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/alphabets/_alphabets.py#L580-L726), and [`docs/ragged.md` lines 86–121](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/docs/ragged.md#L86-L121).

12. **Measure sequence length and base composition.** `sp.length`, `sp.gc_content`, and `sp.nucleotide_content` compute per-sequence nonempty length, G/C counts or proportions, and counts/proportions for every symbol in a supplied nucleotide alphabet. GC and nucleotide content handle dense character and OHE arrays. **Exposure:** documented root API; GC and nucleotide content are in the quick start. **Restrictions:** dense inputs only (no Ragged overload); S1 arrays need explicit axes, OHE GC needs alphabet and OHE axis, and string nucleotide content needs an alphabet; comparisons are uppercase/case-sensitive and normalized denominators are the full sequence-axis width. Evidence: [`_analyzers.py` lines 10–135](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/_analyzers.py#L10-L135).

13. **Count k-mers in one sequence (nonpublic).** `seqpro._analyzers.count_kmers_seq(seq, k)` returns a dictionary of observed k-mers and counts. **Exposure:** source-only helper; it is not exported from `seqpro`, not included in the API docs, and has no example. **Restrictions:** exactly one ASCII string, and `len(seq) >= k`; the adjacent batch `_count_kmers` function immediately raises `NotImplementedError`, so SeqPro has no public batch k-mer counter. Evidence: [`_analyzers.py` lines 138–209](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/_analyzers.py#L138-L209), root exports in [`__init__.py` lines 13–42](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/__init__.py#L13-L42).

14. **Represent variable-length and nested collections with `Ragged`.** `sp.rag.Ragged` can be built from lengths, offsets, an Awkward array, or as an empty container; it stores flat NumPy data plus offsets and supports fixed leading/trailing dimensions. Current constructors support one or **two** ragged axes (a tuple of outer counts and inner lengths); three or more are rejected. It can represent S1 character sequences, opaque byte strings, numeric/OHE data, and string collections nested under another axis. **Exposure:** `Ragged`, `is_rag_dtype`, and `lengths_to_offsets` are documented on the Ragged API page, and the guide illustrates one-axis construction; the current R=2 nested capability is source-only and contradicts stale prose calling the type a one-ragged-axis special case. **Restrictions:** access is through `sp.rag.Ragged`, not `sp.Ragged`; current `Ragged` inherits `NDArrayOperatorsMixin`, not `ak.Array` (the guide's “subclass of ak.Array” sentence is stale), although conversion to/from Awkward is supported. Evidence: [`rag/_core.py` lines 85–209](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/rag/_core.py#L85-L209), [`docs/ragged.md` lines 1–45](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/docs/ragged.md#L1-L45).

15. **Select, reshape, calculate on, and interchange Ragged collections.** `Ragged` exposes row/slice/mask/integer-array indexing (including multi-leading-axis and two-level inner selection), `np.newaxis`, `lengths`, `data`, `offsets`, `shape`, `dtype`, `is_empty`, `is_contiguous`, `is_base`, `view`, elementwise arithmetic/NumPy ufuncs, `reshape`, `squeeze`, `to_packed`, `to_padded`, `to_numpy`, and `to_ak`. String/char views convert zero-copy through `to_chars()` and `to_strings()`. These operations make large heterogeneous designed collections workable without padding first. **Exposure:** core class methods are picked up by the documented `Ragged` class; the guide explicitly covers construction, indexing, ufuncs, and records, but most advanced selection, two-level padding, string conversion, and packing modes are only discoverable in method docs/source. **Restrictions:** ufunc operands must share offsets; record layouts reject whole-record ufuncs/view and must be handled fieldwise; dense conversion requires rectangular lengths unless validation is bypassed; module-level `sp.rag.to_padded` is more restricted (one final ragged axis, nonrecord) than the method, whose R=2 mode can pad the inner axis or both but not the outer axis alone. Evidence: [`rag/_core.py`](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/rag/_core.py), [`rag/_ops.py` lines 231–338](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/rag/_ops.py#L231-L338), [`docs/ragged.md` lines 19–67](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/docs/ragged.md#L19-L67).

16. **Bundle sequences/variants and annotations into record Ragged arrays.** `sp.rag.zip({...})` / `Ragged.from_fields({...})` makes a structure-of-arrays record whose fields share offsets; fields can be retrieved by key or attribute and assigned, rows can be selected, and `data`/`dtype`/`to_numpy` return per-field structures. Numeric, char, opaque-string-under-axis, and R=2 fields are supported. **Exposure:** record Ragged is documented with examples in the Ragged guide; `sp.rag.zip` itself is publicly exported in source but omitted from the Ragged API page's explicit member list. **Restrictions:** at least one field; equal offsets; no record-of-record and no R>=3; many whole-record operations are unavailable. Evidence: [`rag/__init__.py` lines 9–29](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/rag/__init__.py#L9-L29), [`rag/_core.py` lines 211–245](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/rag/_core.py#L211-L245), [`docs/ragged.md` lines 124–181](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/docs/ragged.md#L124-L181).

17. **Concatenate corresponding variable-length rows.** `sp.rag.concatenate(rags, axis)` joins each group's sequence/elements from multiple Ragged inputs along the ragged axis and returns a packed Ragged. **Exposure:** publicly exported source API, but absent from the Ragged API page and tutorial. **Restrictions:** at least one input; same groups/shape/layout; only the ragged axis; documented implementation scope is fixed-itemsize numeric data, not record layouts. Evidence: [`rag/_ops.py` lines 341–407](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/rag/_ops.py#L341-L407), [`rag/__init__.py` lines 17–29](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/rag/__init__.py#L17-L29).

18. **Hash every string in a variable-length collection.** `rag.hash(...)` / `sp.rag.hash(...)` calculates independent MD5, SHA-256, or RapidHash digests in parallel for opaque-string or S1-char leaves at any supported ragged depth. This can provide identity/deduplication keys for designed variants. **Exposure:** public method and submodule export added in 0.21.0, but omitted from the Ragged API page/tutorial; it is documented in source docstrings and changelog. **Restrictions:** string leaves only, not numeric or record layouts; seed only for RapidHash; result is a dense array for a flat string collection and a Ragged when another grouping axis remains. Evidence: [`rag/_ops.py` lines 410–500](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/rag/_ops.py#L410-L500), [`CHANGELOG.md` lines 34–39](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/CHANGELOG.md#L34-L39).

19. **Compose reusable/random augmentation pipelines.** `sp.transforms.Sequential`, `Random`, `ReverseComplement`, `KShuffle`, and `Jitter` wrap the corresponding functions as callables; `ReverseComplement` can reverse a DNA tensor while flipping aligned track tensors, and `Random(p, ...)` probabilistically applies one or more transforms. **Exposure:** `transforms` is a root public submodule and these classes are in its `__all__`, but there is no documentation-site API page or user example for them. **Restrictions:** wrappers are array-oriented and hard-code DNA for reverse complement/k-shuffle; the `Tokenize` class exists in `augmentation.py` but is not imported/exported by `seqpro.transforms`, so it is source-only. Evidence: [`transforms/__init__.py`](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/transforms/__init__.py), [`transforms/augmentation.py` lines 12–122](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/transforms/augmentation.py#L12-L122).

20. **Read, standardize, resize, sort, and convert genomic interval collections.** `sp.bed.read` reads BED3–BED12, narrowPeak, or broadPeak (including `.gz`) to typed Polars frames; `sp.bed.with_len` expands/shrinks each interval about its center or narrowPeak summit; `sort` uses natural chromosome order; `to_pyr`/`from_pyr` interchange with PyRanges; `detect_schema`, `set_schema`, and `CoordSchema` recognize/rename BED, PyBedTools-like, PyRanges, GTF, and GFF coordinate columns and preserve zero/one-based metadata. **Exposure:** documented `seqpro.bed` API, though not in the quick start. **Restrictions:** `with_len` can produce negative starts (no chromosome-bound clipping); PyRanges conversion may reorder rows; this manages coordinates but does not fetch genomic sequence. Evidence: [`bed.py` lines 26–199](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/bed.py#L26-L199), [`_coords.py`](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/_coords.py), [`docs/api/bed.md`](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/docs/api/bed.md).

21. **Scan GTF/GFF annotations and extract attributes.** `sp.gtf.scan(path)` lazily reads the nine standard columns; `sp.gtf.attr(name)` creates a Polars expression that parses a named string attribute. ### Scope boundary established from the public surface

SeqPro's de novo design surface is narrow: the only public from-scratch sequence generator is independent uniform nucleotide sampling, while k-shuffle makes controls from existing sequences. The public exports contain **no** variant enumerator, systematic substitution/indel mutator, combinatorial/degenerate-library constructor, codon optimizer or reverse translator, constrained sampler/optimizer, primer/barcode designer, synthesis-screening rules, diversity/coverage planner, FASTA/FASTQ reader/writer, or genomic sequence extractor. Protein support consists principally of AA encoding/decoding and nucleotide-to-protein translation; it does not include protein-library generation. Evidence is the complete root API in [`python/seqpro/__init__.py` lines 3–42](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/__init__.py#L3-L42) and the package's documented API member list in [`docs/api/index.md`](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/docs/api/index.md).

## A. FACTUALLY WRONG

1. **Ragged is not limited to exactly one ragged axis.** The record says, “`sp.rag.Ragged` … exactly one ragged axis” and repeats “`Ragged` … exactly one ragged axis.” Current 0.22.0 supports one **or two** ragged axes: `Ragged.from_lengths(data, (outer_counts, inner_lengths))` constructs a shape containing two `None` dimensions, while `from_offsets` rejects only `shape.count(None) >= 3`. Correct fact: R=2 nested Ragged arrays, including nested indexing/packing/padding and record fields, are implemented; R>=3 is unsupported. Evidence: [`rag/_core.py` lines 130–209](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/rag/_core.py#L130-L209) and the extensive R=2 implementation in [`rag/_core.py`](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/rag/_core.py). The documentation's one-axis prose is stale relative to the current software.

2. **Absence of `experimental/__init__.py` does not make the subpackage unimportable.** The record says, “`seqpro.experimental` is therefore not an importable package” and later, “its containing directory has no `__init__.py` … so it cannot be imported at all.” Correct fact: under Python's namespace-package rules, the installed `seqpro/experimental/` directory is an implicit namespace package; the 0.22.0 wheel includes `_experimental.py` and `_visualizers.py`, and `from seqpro.experimental._experimental import edit_distance` is importable in an otherwise complete SeqPro environment. What is true is narrower: it is unsupported, not root-exported, and `_visualizers.py` itself fails because of stale imports. Evidence: the modules in the [repository directory](https://github.com/ML4GLand/SeqPro/tree/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/experimental), the [PyPI 0.22.0 distribution](https://pypi.org/project/seqpro/), and Python's [namespace-package import specification](https://docs.python.org/3/reference/import.html#namespace-packages).

3. **`sp.Ragged` is not a root API name.** The unqualified quotation used as API guidance says variable-length batches go to “`sp.Ragged`.” Correct fact: `Ragged` is absent from root `seqpro.__all__`; users access `sp.rag.Ragged` or import `Ragged` from `seqpro.rag`. The record uses the correct name elsewhere but never flags the quoted documentation error. Evidence: [`seqpro/__init__.py` lines 13–42](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/__init__.py#L13-L42), [`rag/__init__.py` lines 17–29](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/rag/__init__.py#L17-L29).

4. **Built-in `sp.AA.translate` does not generally translate RNA containing `U`.** The record says, “`sp.AA.translate()` translates DNA/RNA→AA.” Correct fact: built-in `sp.AA` is constructed from a DNA codon table containing `T` and no `U`; with the default policy, a codon containing `U` becomes `X` (or is dropped with `unknown="drop"`, or errors under validation). RNA translation is possible only by constructing a suitable custom `AminoAlphabet`. Evidence: the built-in table and constructor in [`alphabets/__init__.py` lines 3–73](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/alphabets/__init__.py#L3-L73) and the explicit A/C/G/T unknown policy in [`_alphabets.py` lines 464–508](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/alphabets/_alphabets.py#L464-L508). This is also a README/current-code mismatch that the record repeats without qualification.

5. **Coordinate schemas do not implement open/closed conventions or coordinate conversion.** The record says the five schemas cover “0- vs 1-based and open vs closed interval conventions” and calls this “coordinate-schema handling … for 0- vs 1-based and open vs closed intervals.” Correct fact: `CoordSchema` has only a Boolean `zero_based` field; it has no endpoint-closure field. `set_schema` renames coordinate/strand columns and attaches target zero-based metadata to a Polars result, but it does not add/subtract coordinates to convert between systems. Evidence: [`_coords.py` lines 10–29 and 100–137](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/_coords.py#L10-L137).

6. **Plotting symbols do exist in the source tree.** The record's broad claim says there is no “plotting … symbol … anywhere in the 27 Python source files,” and that grep for `plot|visual` returned no substantive hits. Correct fact: `experimental/_visualizers.py` imports Matplotlib and defines `plot_gc_content` and `plot_nucleotide_content`. They are unsupported and currently broken, as the record correctly explains later, but that does not make the earlier source-wide absence claim true. Evidence: [`experimental/_visualizers.py`](https://github.com/ML4GLand/SeqPro/blob/63a843985d96dd3f5a7bc8cc20e8bd03f1dabdd9/python/seqpro/experimental/_visualizers.py).

7. **Only 0.22.0 has the cited BREAKING CHANGE entry.** The record says, “0.22.0 and 0.21.x carry BREAKING CHANGE entries for `Ragged.__getitem__` semantics.” Correct fact: the current changelog has one `BREAKING CHANGE` heading, under 0.22.0; the 0.21.x entries are fixes/features/performance entries and contain no breaking-change heading. ## C. BALANCE

The record is limitation-heavy rather than balanced: most of its space proves absent design features repeatedly, while SeqPro's positive surface is compressed into a late “notable capabilities” list. It does give unusually strong credit to TMM, Ragged records/hashing, Xarray/Dask, translation policies, interval handling, and engineering/maintenance, so it is not dismissive. Nevertheless, the false one-axis characterization removes a major current Ragged strength, and important operational modes—nested collections, synchronized jitter, masked/in-place Ragged reverse complement, encoding unknowns, and actual call restrictions—receive little or no space. As a factual portrait of SeqPro it is broadly well researched but not proportionate: limitations are documented in substantially greater depth than capabilities.
