Snapshot date: 2026-08-14. I treated the newest PyPI artifact, release tag, default-branch source, current Read the Docs pages, and the supplied paper as distinct primary-source snapshots. The installable release and the default branch both identify as 1.4.0; the default branch has a later, non-code commit. ### Identity, availability, installation, and maintenance

- **Current version and release date:** **1.4.0, released/uploaded 2026-06-25**. PyPI marks 1.4.0 as the current release and dates both wheel and source upload June 25; GitHub marks `v1.4.0` “Latest.” The package source says `__version__ = '1.4.0'`. Evidence: [PyPI release history and files](https://pypi.org/project/tangermeme/), [GitHub 1.4.0 release](https://github.com/jmschrei/tangermeme/releases/tag/v1.4.0), and [`tangermeme/__init__.py`](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/__init__.py#L1-L4).
- **License:** **MIT**, not the CC BY license printed on the preprint itself. The package metadata declares MIT and the repository contains the MIT text. Evidence: [`pyproject.toml`, lines 5–12](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/pyproject.toml#L5-L12), [`LICENSE`](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/LICENSE), and [paper, p. 9](/mnt/c/Users/zhliu/Desktop/KinneyLab/25_poolparty_private/revision/tool_survey/papers/Schreiber2025_tangermeme_all.pdf).
- **Installation and platform:** ordinary installation is `pip install tangermeme` or `uv add tangermeme`; Python **>=3.10** is required. The package declares PyTorch >=2.0 and scientific-Python dependencies. Optional `docs` and `interactive` extras build documentation and add `mpld3`; contributors clone the repository and run `uv sync --extra dev`. Evidence: [README, lines 18–47](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/README.md#L18-L47) and [`pyproject.toml`, lines 5–69](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/pyproject.toml#L5-L69).
- **Maintenance:** **actively maintained.** Releases 1.3.0 and 1.4.0 appeared on June 23 and June 25, 2026, after 1.0.2–1.2.0 releases earlier in 2026; the default branch then received a commit on 2026-07-19. Version 1.4 added a design algorithm and repaired/rendered design documentation, which is substantive current development rather than archival churn. Evidence: [PyPI release history](https://pypi.org/project/tangermeme/#history), [GitHub releases](https://github.com/jmschrei/tangermeme/releases), [1.4 release notes, lines 9–22](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/docs/whats_new.rst#L9-L22), and [2026-07-19 default-branch commit](https://github.com/jmschrei/tangermeme/commit/8d732b8c08764057b7ae5faa644d48664f36b44b).
- **Project/interface:** tangermeme is a Python/PyTorch “everything-but-the-model” library. The user supplies a trained model/oracle; tangermeme does not train models or ship a model zoo. Its library operations are Python functions over tensors. The only current console entry point is `tangermeme-install-skills`, which installs bundled coding-agent guidance, not a sequence-design program. The former FIMO/Tomtom command-line tools moved to the separate memesuite-lite project. Evidence: [README, lines 10 and 49–82](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/README.md#L10-L82), [`pyproject.toml`, lines 71–78](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/pyproject.toml#L71-L78), and [paper, pp. 1–3](/mnt/c/Users/zhliu/Desktop/KinneyLab/25_poolparty_private/revision/tool_survey/papers/Schreiber2025_tangermeme_all.pdf).

| Random de novo screening and top-*n* library selection | `tangermeme.design.screen(model, shape, y=..., loss=..., n_best=..., func=...)` repeatedly generates candidate batches (default `utils.random_one_hot`), scores them with the model, retains the `n_best` lowest-loss sequences, and returns them ranked. `y=None` instead seeks the strongest mean model response. | Greedy motif/substitution design of a template | `design.greedy_substitution(model, X, y, motifs, ...)` tries every motif at every allowed start position each round and commits the single edit with greatest loss improvement. If `motifs=None`, it uses single alphabet characters, giving single-character mutation design rather than motif-only design. | Core, documented API with extensive Tutorial B6 examples. | It designs **one fixed-length sequence per call** (`X` batch size 1) and returns one sequence. | Beam-search motif/substitution design and small ranked collections | `design.beam_substitution(...)` generalizes greedy substitution: each round expands every complete sequence in a beam by all motif-position edits, carries existing beam members forward, de-duplicates identical sequences, keeps the global best `beam_size` by absolute loss, and returns up to `n_best` distinct full-length sequences ranked low-to-high loss. `beam_size=1` recovers the greedy trajectory for matching settings. | Core, documented API and tutorial; **new in 1.4.0 (2026)**, hence absent from the 2025 software snapshot described by the supplied paper. | Same one-template, fixed-length, string-motif, mask, custom-loss, and user-oracle requirements as greedy design. Here `max_iter=-1` means no iteration limit, unlike `greedy_substitution`. | [1.4 release](https://github.com/jmschrei/tangermeme/releases/tag/v1.4.0); [design API](https://tangermeme.readthedocs.io/en/latest/api/design.html#tangermeme.design.beam_substitution.beam_substitution); [`beam_substitution.py`, lines 25–72, 82–174, 219–306](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/design/beam_substitution.py#L25-L306); [Tutorial B6 beam section](https://tangermeme.readthedocs.io/en/latest/tutorials/Tutorial_B6_Design.html#beam-search) |
| Background-averaged construct design | `design.greedy_marginalize(model, X_backgrounds, y_delta, motifs, ...)` greedily chooses motif identities, orientations, overlaps, positions, and flank spacings to build a variable-width construct whose **average marginal effect** approaches `y_delta`. The first motif is tested centrally; later motifs are tried within `max_spacing` of current construct flanks and may overwrite/overlap earlier motifs. It returns the construct, not a full background sequence. | Core, documented 1.4 API and Tutorial B6. | `X` is a set of backgrounds, and `y` means `f(X + construct) - f(X)`, not an absolute target. 1. **Quote:** “**Data model:** every sequence collection is a bare `torch.Tensor` of shape `(-1, len(alphabet), length)`.”

   **Correct fact:** support is operation-dependent. `predict` handles tensor or list/tuple outputs, and `saturation_mutagenesis(raw_outputs=True)` can return multiple output tensors, but default ISM aggregation explicitly rejects them; `deep_lift_shap` requires a single `(batch, n_targets)` tensor; and current design implementations index `y_orig.shape` and tensor masks, so list-valued model outputs require a wrapper despite their broad type hints. The record has repeated a paper-level generalization as a universal current-software fact. [`predict` output handling](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/predict.py#L86-L94); [`saturation_mutagenesis` restriction](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/saturation_mutagenesis.py#L94-L102); [`deep_lift_shap` restriction](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/deep_lift_shap.py#L255-L259); [`greedy_substitution` tensor-only use](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/design/greedy_substitution.py#L153-L177).

6. **Quote:** “**RENDER THIS CELL AS: ‘Python API only (no CLI, no GUI, no web service)’**.”

   **Correct fact:** current tangermeme does ship one console command, `tangermeme-install-skills`. It installs bundled agent guidance rather than analyzing or designing sequences, so “Python analysis/design API plus one installation-only CLI; no analysis CLI, GUI, or web service” is accurate, while “no CLI” is not. [`pyproject.toml` console entry point](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/pyproject.toml#L71-L78); [1.4 release note](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/docs/whats_new.rst#L30-L33).

7. **Quote:** “**Alphabet-agnostic throughout** — README's claim: ‘…all functions are extensible to any alphabet.’”

   **Correct fact:** arbitrary categorical alphabets are supported by many tensor operations, but not “throughout.” Reverse complementation and GC content are DNA-semantic, greedy/beam design defaults to DNA reverse complements, and `greedy_marginalize` replays chosen string motifs through `substitute` without forwarding the user alphabet on later iterations. This is qualified generic categorical support, not complete or uniformly reliable protein support. [`reverse_complement`](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/utils.py#L507-L576); [`gc_content`](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/utils.py#L896-L935); [`greedy_marginalize` custom-alphabet setup and replay](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/design/greedy_marginalize.py#L161-L204).

8. **Quote:** “Design is discrete and greedy.”

   **Correct fact:** current design is discrete/combinatorial, but it is not all greedy. The 1.4 package exports random `screen`, `greedy_substitution`, `beam_substitution`, and `greedy_marginalize`; beam search deliberately retains multiple trajectories and random screening has no greedy edit trajectory at all. [`design.__all__`](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/design/__init__.py#L4-L14); [`screen` description](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/design/screen.py#L37-L48); [`beam_substitution` description](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/design/beam_substitution.py#L44-L67); [1.4 release notes](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/docs/whats_new.rst#L9-L22).

9. **Quote:** “the only sequences it ever hands back are DeepLIFT backgrounds, generated controls, and design winners.”

   **Correct fact:** every public `ersatz` transformation returns sequences: `insert` returns longer sequences, `substitute` and `multisubstitute` return fixed-length edited sequences, and `delete` returns shorter sequences, in addition to the control generators named by the record. [`ersatz.insert`](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/ersatz.py#L20-L94); [`substitute`](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/ersatz.py#L97-L195); [`multisubstitute`](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/ersatz.py#L198-L297); [`delete`](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/ersatz.py#L300-L340).

## B. INCOMPLETE

1. **Random de novo screening (`design.screen`) is only named and credited with `n_best`.** It accepts a custom candidate generator, generates independent batches, optimizes either a target/loss or raw response, permits an unlimited run with `max_iter=-1`, and does not de-duplicate retained candidates. [`screen` API and source](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/design/screen.py#L19-L185). **Why material:** this is tangermeme's direct interface for generating and selecting a de novo collection, not merely another motif-placement search.

2. **Background-averaged construct design (`design.greedy_marginalize`) is mentioned too briefly to convey its mode.** It optimizes a desired change `f(X + construct) - f(X)` over a **set of backgrounds**, searches motif identity, orientation, overlap, position, and spacing near the construct flanks, and returns one variable-width construct rather than an edited background. [`greedy_marginalize` source](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/design/greedy_marginalize.py#L22-L61); [bundled current design guide](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/_skills/data/references/design.md#L83-L97). **Why material:** it is the only current algorithm that designs a portable motif construct by averaging away background context.

3. **Important design-objective modes and restrictions are scattered or absent.** `greedy_substitution` and `beam_substitution` support raw-response maximization with `y=None`, arbitrary per-candidate losses, `output_mask`, and single-character design with `motifs=None`; both are fixed-length substitution searches from one template, while only beam returns multiple distinct winners. [`greedy_substitution` signature and contract](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/design/greedy_substitution.py#L24-L147); [`beam_substitution` signature and contract](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/design/beam_substitution.py#L25-L174). **Why material:** these controls determine whether the package can express a user's actual design objective and whether the result is one sequence or a ranked variant set.

4. **The true insertion and deletion sequence generators are relegated to a tutorial list.** `ersatz.insert` retains the whole template and returns a longer batch; `ersatz.delete` excises a half-open interval and returns a shorter batch. Insert currently rejects starts greater than `sequence_length - motif_length`, even though output length grows; both use one coordinate across the batch. [`insert`](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/ersatz.py#L20-L94); [`delete`](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/ersatz.py#L300-L340). **Why material:** readers otherwise miss that core tangermeme can materialize variable-length indel collections even though its oracle-guided designers cannot search indels.

5. **Masked/paired substitution semantics are omitted.** `ersatz.substitute` can broadcast one motif or pair one motif with each input, and all-zero motif columns/default string `N` preserve the original character; `multisubstitute` centers and applies a multi-motif arrangement with explicit gaps. [`substitute`](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/ersatz.py#L97-L195); [`multisubstitute`](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/ersatz.py#L198-L297). **Why material:** these are useful batch-library construction modes, especially for degenerate constructs and per-member motif assignments, not just generic “motif implantation.”

6. **Control-library independence and diversity restrictions are missing.** `shuffle` applies the same positional permutation to every sequence in a batch for a given replicate; `dinucleotide_shuffle` fixes the selected region's first and last characters and can warn or fail when low diversity prevents the requested distinct shuffles. [`shuffle` documented behavior](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/ersatz.py#L425-L498); [`dinucleotide_shuffle`](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/ersatz.py#L529-L688). **Why material:** these details affect whether generated controls are statistically independent and how much library diversity they really contain.

7. **`predict` as a candidate-library scoring engine is underdescribed.** It batches collections that do not fit GPU memory, can retain the source as int8 and upcast batches, forwards aligned auxiliary inputs, post-processes outputs, supports tensor/list outputs, and restores model device/training state; however, auxiliary integer and Boolean inputs are cast to the model dtype unless wrapped. [`predict`](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/predict.py#L17-L165). **Why material:** scalable oracle scoring is the bridge from a generated variant collection to ranking and selection.

8. **Variant-effect indel normalization is not explained.** `deletion_effect` expects an input padded by the maximum deletion count and trims the reference for equal model length; `insertion_effect` lengthens then trims a flank selected by `left`. The functions return before/after outputs, not edited sequences. [`variant_effect.py`](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/variant_effect.py#L124-L404). **Why material:** without this restriction, “deletion/insertion effects” sounds like arbitrary variable-length-model support when it is actually fixed-model-length scoring.

9. **The paired-versus-product distinction is not made explicit.** `apply_product` evaluates every independent combination of `X` and auxiliary axes, while `apply_pairwise` crosses each sequence with index-zipped auxiliary contexts; the latter is public and documented in source/bundled guidance but omitted from the rendered Sphinx member list. [`product.py`](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/product.py#L30-L349); [rendered member list source](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/docs/api/product.rst). **Why material:** choosing the wrong interface changes the biological context set being evaluated and can multiply a library into invalid combinations.

10. **`utils.chunk` / `unchunk` are absent.** They tile variable-length sequence collections into overlapping fixed model windows and reconstruct base-resolution outputs; incomplete terminal windows are discarded, and current `unchunk` requires original lengths despite a `None` default. [`utils.py`, lines 649–786](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/utils.py#L649-L786). **Why material:** this is the package's built-in way to score long or variable-length collections with fixed-window models.

11. **FASTA export's ambiguity restriction is omitted.** `io.one_hot_to_fasta` is a public, tested source function omitted from the rendered I/O member list, and it calls `characters` without exposing `force`/`allow_N`; ambiguous, tied, or all-zero columns can therefore fail—including all-zero positions that may occur in a construct returned by `greedy_marginalize`. [`one_hot_to_fasta`](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/io.py#L540-L587); [`characters`](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/utils.py#L338-L410). **Why material:** this determines whether a designed tensor can actually be exported without custom decoding.

12. **Motif-library ingestion and hard-consensus conversion are barely mentioned.** `io.read_meme` loads named PWMs, `utils.pwm_consensus` converts each to an argmax one-hot motif, and `characters` supplies the string accepted by design calls; ties choose the earliest channel and all-zero columns remain zero. [`read_meme`](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/io.py#L590-L619); [`pwm_consensus`](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/utils.py#L789-L822). **Why material:** it is the supported path from a motif database to the discrete motif vocabulary used in sequence design, and it makes clear that design does not optimize or sample PWMs directly.

13. **Reproducibility and sequence diagnostics are incomplete.** `gc_content` excludes all-zero positions, `entropy` and `information_content` operate per position on PWMs/one-hot batches, and unmentioned `set_seed` seeds Python, NumPy, Torch, and CUDA; none is enforced as a design constraint, and explicit `random_state` arguments take precedence. [`utils.py`, lines 874–1016](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/utils.py#L874-L1016). **Why material:** these are the only built-in composition/diversity diagnostics and global reproducibility helper for generated collections.

14. **Seqlet-discovery restrictions are incomplete.** Both callers require projected 2-D attribution tracks; `recursive_seqlets` calls only positive seqlets, assumes equal-length examples, and prevents core overlap, while `tfmodisco_seqlets` is only the seqlet-calling stage rather than the full external TF-MoDISco workflow. [`seqlet.py`](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/seqlet.py#L211-L577). **Why material:** these restrictions shape which candidate motifs/parts can be discovered and subsequently supplied to the design APIs.

15. **Matched-background output semantics are incomplete.** `match.extract_matching_loci` returns sorted coordinates rather than sequences and does not preserve one-to-one pairing with input loci; GC matching is binned, scarce bins spill to neighbors, and high-N query loci can be dropped. [`extract_matching_loci`](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/tangermeme/match.py#L372-L621). **Why material:** these backgrounds drive marginal-effect estimates and construct design, so treating them as paired controls would change the analysis.

16. **The paper/current-software boundary is not stated.** The supplied August 2025 paper reports tangermeme **0.5.1** for its benchmark, whereas the surveyed software is 1.4.0 and now includes later design APIs, most visibly `beam_substitution`; conversely, former FIMO/Tomtom CLIs have moved out. [paper, Methods/software versions, pp. 6 and 9](/mnt/c/Users/zhliu/Desktop/KinneyLab/25_poolparty_private/revision/tool_survey/papers/Schreiber2025_tangermeme_all.pdf); [current 1.4 history](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/docs/whats_new.rst#L9-L22); [current README migration warning](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/README.md#L65-L78). **Why material:** without the version boundary, paper-wide statements can be mistaken for verified properties of the current implementation, as happened with universal multi-output support.

17. **Installation commands are absent.** Current primary instructions are `pip install tangermeme` or `uv add tangermeme`; Python >=3.10 and PyTorch >=2.0 are required. [README installation section](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/README.md#L18-L47); [`pyproject.toml`](https://github.com/jmschrei/tangermeme/blob/8d732b8c08764057b7ae5faa644d48664f36b44b/pyproject.toml#L5-L35). **Why material:** version, license, and maintenance are recorded, but a reader still cannot tell from the record how the current package is obtained.

## C. BALANCE

The record is **not fully balanced**. It is unusually conscientious about several real strengths—motif placement, spacing sweeps, control generation, beam/screen top-*n* outputs, composable perturbation/model operations, interpretation tools, and active maintenance—and it corrects some prior understatements. Even so, it documents absent pooled-library abstractions and wet-lab features at much greater depth than it explains the four current design algorithms, especially de novo `screen` and background-averaged `greedy_marginalize`; its concluding absolute claim that tangermeme returns only controls, DeepLIFT references, and design winners erases the core sequence-returning Ersatz transformations. Capabilities are therefore substantial but not given proportionate, consistently accurate space relative to limitations.
