### Capability 1 — interactive MPRA power-guided library sizing

- **What it does.** The Shiny **Power** tab plots estimated two-sample t-test power over absolute transcriptional shifts from 0 to 5 in 0.05 steps. Users vary activity standard deviation (`sigma`), number of tested variants (`nsnp`), transfection replicates (`nBlock`), barcode replicates (`nbarcode`), and nominal alpha. The calculation uses `n = nbarcode * nBlock`, standardized effect `meanDiff / sigma`, and Bonferroni level `alpha / nsnp`; input changes update the plot. This helps choose replicate/barcode counts but does not automatically optimize or emit a recommended design.
- **Interface/status.** User-facing, documented Shiny interface (`Power` tab), implemented in `designMPRA/server.R`; it is **not an exported `mpradesigntools` R-package function**.
- **Restrictions.** It assumes barcode/transfection observations can be treated as independent, identically distributed and approximately normal; it ignores large batch effects; the supplement explicitly calls the estimates approximate rough guidelines because true effect sizes and activity dispersion are unknown a priori. “Variance” in one prose list means the `sigma`/standard-deviation input used in code. This sizes MPRA replication, not DNA length or synthesis capacity.
- **Evidence.** [Shiny inputs and caveats, `ui.R` lines 16–33 and 88–105](https://github.com/andrewGhazi/designMPRA/blob/0cf56ee602fc86dde705906d071a39cbdf6e99a8/ui.R#L16-L33); [power formula, `server.R` lines 24–38](https://github.com/andrewGhazi/designMPRA/blob/0cf56ee602fc86dde705906d071a39cbdf6e99a8/server.R#L24-L38); paper PDF p. 2 §2 and Fig. 1; PDF pp. 26–27, Supplement S3.4–S4.

### Capability 2 — prepare simple VCF variants for the generator

- **What it does.** Exported `spread_and_fix_indels(vcf_path)` reads a VCF, expands comma-separated ALT alleles onto separate rows, converts simple left-anchored VCF indels to the package's dash convention (for example `REF=A, ALT=ATC` becomes `REF=-, ALT=TC`), returns the fixed table, and writes `*_fixed.vcf` beside the input for subsequent `processVCF()` use.
- **Interface/status.** **Documented and exported package API**, separate from the main generator; absent from the 2018 paper.
- **Restrictions.** Normalization only handles single-base substitutions or a one-base anchor against a longer allele whose first base matches. It errors on two multibase alleles, and mismatched anchors fail/error. Expansion recognizes comma-separated ALT strings. The function writes a file as a side effect to the input directory.
- **Evidence.** [`NAMESPACE` exports](https://github.com/andrewGhazi/mpradesigntools/blob/afd386ef12051bb0a37ad63a6f92acd555246584/NAMESPACE); [`spread_and_fix_indels` documentation and implementation, lines 1358–1448](https://github.com/andrewGhazi/mpradesigntools/blob/afd386ef12051bb0a37ad63a6f92acd555246584/R/processVCFfast.R#L1358-L1448); [generated manual](https://rdrr.io/github/andrewGhazi/mpradesigntools/man/spread_and_fix_indels.html).

### Capability 3 — generate ref/alt MPRA oligo collections from a VCF

- **What it does.** Exported `processVCF(...)` reads a VCF, expands each comma-separated alternate allele, retrieves human genomic context from `BSgenome.Hsapiens.UCSC.hg38`, and produces `nper` barcoded reference constructs plus `nper` barcoded alternate constructs for each expanded variant. It recognizes canonical one-base SNVs, dash-coded insertions (`REF='-'`), and dash-coded deletions (`ALT='-'`). Each successful row is labeled with variant ID, `ref`/`alt` type, allele, within-variant and global indices, barcode, full DNA sequence, optional site-fix metadata, and notes.
- **Interface/status.** `processVCF` is the package's **main documented and exported API**. `processSnp` is Rd-documented on rdrr but not exported; it is the internal per-variant worker. The paper documents only the VCF-to-TSV workflow, not function names/signatures.
- **Restrictions.** It is DNA/regulatory-MPRA construct generation only—no protein/amino-acid library design. It does not discover, prioritize, phase, or combinatorially combine variants; it generates constructs for user-supplied VCF rows and no automatic positive/negative controls. Multinucleotide substitutions and complex alleles that are neither recognized SNVs nor dash indels return a failure. Source accesses at least `ID`, `CHROM`, `POS`, `REF`, `ALT`, and `INFO`; chromosome lookup prepends `chr`, and no REF-vs-hg38 validation is implemented. It is serial (parallelization remains a planned feature).
- **Evidence.** [`processVCF` manual/source lines 997–1115](https://github.com/andrewGhazi/mpradesigntools/blob/afd386ef12051bb0a37ad63a6f92acd555246584/R/processVCFfast.R#L997-L1115); [variant classification and hg38 worker lines 227–234](https://github.com/andrewGhazi/mpradesigntools/blob/afd386ef12051bb0a37ad63a6f92acd555246584/R/processVCFfast.R#L227-L234); [failure for other allele types, lines 967–974](https://github.com/andrewGhazi/mpradesigntools/blob/afd386ef12051bb0a37ad63a6f92acd555246584/R/processVCFfast.R#L967-L974); [result schema/output lines 1241–1341](https://github.com/andrewGhazi/mpradesigntools/blob/afd386ef12051bb0a37ad63a6f92acd555246584/R/processVCFfast.R#L1241-L1341); [README planned features lines 126–133](https://github.com/andrewGhazi/mpradesigntools/blob/afd386ef12051bb0a37ad63a6f92acd555246584/README.md#L126-L133); paper PDF pp. 1–2, Abstract and §3.

### Capability 4 — control context, primers, enzyme patterns, layout, and oligo length

- **What it does.** `processVCF` exposes independently adjustable upstream and downstream context lengths; required forward and reverse primer strings; three restriction-recognition patterns (defaults KpnI `GGTACC`, XbaI `TCTAGA`, SfiI `GGCCNNNNNGGCC`); optional extra `TG` and `GGC` elements; and an optional maximum construct size that trims context evenly from both sides. Recognition strings may contain `N` ambiguity. `enzyme1` and `enzyme2` are inserted into the output; `enzyme3` is screened but not inserted. Current default package layout is `forward primer – allele-bearing context – enzyme1 – enzyme2 – barcode – reverse primer`; `extra_elements=TRUE` changes it to the paper/web layout by adding `TG` before context and `GGC` before the reverse primer.
- **Interface/status.** All are **documented `processVCF` arguments**; `alter_aberrant`, `extra_elements`, and `max_construct_size` are explicitly labeled “under development.” The paper and web UI present the TG/GGC layout as the web workflow's fixed layout and identify default web primers, but the package requires the primer arguments and defaults `extra_elements` to false.
- **Restrictions.** A maximum is enforced only when the user supplies `max_construct_size`; trimming subtracts `ceiling(excess/2)` from both context sides and does not expose a minimum-context guard. The output is an oligo cassette, not a complete plasmid/promoter/ORF design.
- **Evidence.** [`processVCF` arguments/details lines 1001–1052 and defaults 1099–1115](https://github.com/andrewGhazi/mpradesigntools/blob/afd386ef12051bb0a37ad63a6f92acd555246584/R/processVCFfast.R#L1001-L1052); [size calculation/trimming lines 249–324](https://github.com/andrewGhazi/mpradesigntools/blob/afd386ef12051bb0a37ad63a6f92acd555246584/R/processVCFfast.R#L249-L324); [sequence assembly lines 401–419](https://github.com/andrewGhazi/mpradesigntools/blob/afd386ef12051bb0a37ad63a6f92acd555246584/R/processVCFfast.R#L401-L419); paper PDF p. 2 §3 and p. 5 Supplement S1.3.

### Capability 5 — strand-aware context and dbSNP reverse-allele handling

- **What it does.** An `MPRAREV` substring in VCF `INFO` tells the package to fetch asymmetric ranges in the opposite order and reverse-complement the genomic construct so the tested allele is oriented relative to the reporter. Separately, `flip_RV=TRUE` (the default) detects an `RV` substring in `INFO`, complements the input allele values, and records a warning note. These are distinct tags/behaviors.
- **Interface/status.** `MPRAREV` is documented in the README and `processVCF` details; `flip_RV` is a **documented current API argument**. The Shiny source supports `MPRAREV`, but the checked-in 2017 web worker predates `flip_RV`. The current README sentence saying RV alleles “need to be flipped manually” is stale relative to the API/source; the same README's planned-feature checklist marks automated RV handling complete.
- **Restrictions.** `MPRAREV` must be supplied manually where appropriate. Only hg38 context is available; mm10 is still listed as planned. The RV code itself warns that the feature is new and asks users to double-check results.
- **Evidence.** [current strand/API documentation lines 1032–1043](https://github.com/andrewGhazi/mpradesigntools/blob/afd386ef12051bb0a37ad63a6f92acd555246584/R/processVCFfast.R#L1032-L1043); [RV implementation/warning lines 286–315](https://github.com/andrewGhazi/mpradesigntools/blob/afd386ef12051bb0a37ad63a6f92acd555246584/R/processVCFfast.R#L286-L315); [MPRAREV assignment lines 1212–1219](https://github.com/andrewGhazi/mpradesigntools/blob/afd386ef12051bb0a37ad63a6f92acd555246584/R/processVCFfast.R#L1212-L1219); [README constraints/plans lines 50–61 and 126–133](https://github.com/andrewGhazi/mpradesigntools/blob/afd386ef12051bb0a37ad63a6f92acd555246584/README.md#L50-L61).

### Capability 6 — choose, filter, and uniquely assign barcode pools

- **What it does.** `processVCF` can use the original precomputed `twelvemers` pool (advertised as 1,140,292 inert 12-mers), any of 27 bundled FreeBarcodes-derived sets named `barcodes3-1` through `barcodes17-2`, or a caller-supplied character vector. In bundled names, the first number is barcode length and the second is the number of indel errors claimed correctable while retaining original-barcode identification. It shuffles the chosen pool, partitions it across input variants, samples without replacement for ref/alt rows, and explicitly checks barcode uniqueness. It can require every barcode to contain A/C/G/T (`ensure_all_4_nuc=TRUE`, default) and exclude caller patterns via `filterPatterns` (default `AATAAA`, a cleavage/polyadenylation motif); the code adds all three enzyme patterns and searches supplied patterns plus reverse complements and reversals.
- **Interface/status.** Barcode selection/filtering is part of the **documented `processVCF` API**. The bundled barcode vectors are documented package data objects. The README lists advertised set sizes (from 1 to 1,636,417); generated Rd pages report each FreeBarcodes vector as one element larger than the README count, so the README table should be treated as the project's advertised capacity rather than a reconciled binary-object audit.
- **Restrictions.** The FreeBarcodes-derived pools “only meet the traditional MPRA barcode requirements to varying degree” and may contain human miRNA seeds; the README tells users to supply relevant miRNA seeds in `filterPatterns`. Custom vectors are accepted only as same-length character n-mers, and the tool merely warns the user to assure length/inertness. Capacity must cover `expanded VCF rows × 2 × nper`; the code calls `barcodes16-1` the largest bundled set. Its capacity check occurs before composition/pattern filtering, so post-filter usable capacity is not prevalidated. There is no user-set random seed argument and no newly synthesized barcode optimization in the runtime API.
- **Evidence.** [barcode argument/details lines 1028–1067](https://github.com/andrewGhazi/mpradesigntools/blob/afd386ef12051bb0a37ad63a6f92acd555246584/R/processVCFfast.R#L1028-L1067); [pool selection/capacity/filtering lines 1150–1219](https://github.com/andrewGhazi/mpradesigntools/blob/afd386ef12051bb0a37ad63a6f92acd555246584/R/processVCFfast.R#L1150-L1219); [uniqueness check lines 977–980](https://github.com/andrewGhazi/mpradesigntools/blob/afd386ef12051bb0a37ad63a6f92acd555246584/R/processVCFfast.R#L977-L980); [README FreeBarcodes warning and size table lines 63–104](https://github.com/andrewGhazi/mpradesigntools/blob/afd386ef12051bb0a37ad63a6f92acd555246584/README.md#L63-L104); [example generated barcode-object page](https://rdrr.io/github/andrewGhazi/mpradesigntools/man/barcodes16-1.html).

### Capability 7 — detect, resample around, or optionally mutate unwanted restriction sites

- **What it does.** The generator counts recognition sites for `enzyme1`, `enzyme2`, and `enzyme3` with ambiguity-aware matching. By default, a variant whose fetched genomic context contains an unwanted site fails. Sites caused by a barcode or element junction trigger barcode resampling, with failure after 40 attempts in the package. With `alter_aberrant=TRUE`, one unwanted site wholly within genomic context can instead be broken by changing a non-`N` base; it creates a set of altered site versions and gives matched alterations to ref and alt constructs so the intended allele comparison is paired. Output can retain original/fixed-site metadata.
- **Interface/status.** `alter_aberrant` is a **documented `processVCF` option marked under development**. Internal `randomly_fix(...)` has a generated Rd page but is not exported. Barcode resampling is automatic internal behavior. The paper only states that barcodes must not generate harmful restriction sites and that enzymes are adjustable; it does not document the current mutation mode.
- **Restrictions.** Mutation mode rejects a site crossing the tested variant and rejects more than one unwanted context site. A site produced at an element boundary is not automatically sequence-edited; barcode-caused cases are resampled and otherwise the variant fails. `enzyme3` is checked because it is used later in library preparation but is not part of the output sequence. Altering context changes biological sequence and is explicitly an under-development option, with the changes reported in `site_fix_info`.
- **Evidence.** [site counter and `randomly_fix`, lines 19–31 and 112–185](https://github.com/andrewGhazi/mpradesigntools/blob/afd386ef12051bb0a37ad63a6f92acd555246584/R/processVCFfast.R#L19-L31); [SNV failure/fix/resampling logic, lines 344–543](https://github.com/andrewGhazi/mpradesigntools/blob/afd386ef12051bb0a37ad63a6f92acd555246584/R/processVCFfast.R#L344-L543); [`enzyme3` documentation lines 1045–1052](https://github.com/andrewGhazi/mpradesigntools/blob/afd386ef12051bb0a37ad63a6f92acd555246584/R/processVCFfast.R#L1045-L1052); [internal `randomly_fix` manual](https://rdrr.io/github/andrewGhazi/mpradesigntools/man/randomly_fix.html); paper PDF p. 2 §3.

### Capability 8 — return/write successful designs and actionable failures

- **What it does.** `processVCF` returns a named list with `result` (labeled sequence rows) and `failed` (variant rows and reasons), permits partial success, prints the output length distribution, and optionally writes a TSV. When a mixed job has an output path, source also saves the full list as an `.RData`; when site fixes are enabled it flattens site-fix detail into the TSV. The Shiny interface previews input/failures and offers an `out.tsv` download.
- **Interface/status.** Return contract and `outPath` are **documented package API**; the extra mixed-job `.RData`, length printout, and flattening behavior are source-level behavior. TSV download is a documented web interface. The paper states only that a TSV is returned and shows an illustrative `ID/type/allele/barcode/sequence` table, not a formal schema.
- **Restrictions.** With all failures, `result` is `NA`; with no failures, `failed` is `NA`. Output generation is stochastic because barcode sampling has no seed parameter. The paper's screenshot uses `mut`, whereas current package/source emits `alt`; the historical screenshot is not the current package contract.
- **Evidence.** [return documentation lines 1068–1071](https://github.com/andrewGhazi/mpradesigntools/blob/afd386ef12051bb0a37ad63a6f92acd555246584/R/processVCFfast.R#L1068-L1071); [output branches lines 1241–1341](https://github.com/andrewGhazi/mpradesigntools/blob/afd386ef12051bb0a37ad63a6f92acd555246584/R/processVCFfast.R#L1241-L1341); [`designMPRA/server.R` download lines 136–166](https://github.com/andrewGhazi/designMPRA/blob/0cf56ee602fc86dde705906d071a39cbdf6e99a8/server.R#L136-L166); paper PDF p. 2 §3 and p. 5 Supplement S1.2.

### Capability 9 — narrower VCF-to-sequence generation through the historical Shiny UI

- **What it does.** The **Create sequences** tab accepts a VCF plus barcodes per allele, a symmetric half-context width, three enzyme patterns, and forward/reverse primers; it retrieves hg38 context, expands comma-separated ALT alleles, handles SNVs and dash-coded insertions/deletions, honors `MPRAREV`, assigns precomputed 12-bp inert barcodes, screens restriction sites, and downloads a TSV. Its fixed construct layout includes `TG` and `GGC`.
- **Interface/status.** This is the documented Shiny user interface and source-loaded `designMPRA/scripts/processVCFfast.R`, not the exported package API. The web generator is described as demonstrative; the UI recommends the package for large jobs and says it is slightly more featureful.
- **Restrictions.** The checked-in server validates `rows × nper × 2 < 20,000`, so exactly 20,000 also fails even though UI prose says “at most 20000.” The UI fixes barcodes at 12 bp and uses symmetric context, has no current package options for custom pools/pattern filters/max-size/context mutation/RV flipping, and can fail variants with unwanted context or junction sites. The source caps the underlying fixed pool at 1,140,292, but the deployed UI imposes the much smaller request cap. It uses only hg38. The endpoint is currently 404, as noted above.
- **Evidence.** [Shiny sequence inputs and restrictions, `ui.R` lines 34–65 and 107–156](https://github.com/andrewGhazi/designMPRA/blob/0cf56ee602fc86dde705906d071a39cbdf6e99a8/ui.R#L34-L65); [web validation/call, `server.R` lines 88–125](https://github.com/andrewGhazi/designMPRA/blob/0cf56ee602fc86dde705906d071a39cbdf6e99a8/server.R#L88-L125); [historical web worker classification/layout/pool, `scripts/processVCFfast.R`](https://github.com/andrewGhazi/designMPRA/blob/0cf56ee602fc86dde705906d071a39cbdf6e99a8/scripts/processVCFfast.R); paper PDF pp. 1–2 and p. 5 Supplement S1.3.

### Capability 10 — create the original inert 12-mer candidate pool (development/example script only)

- **What it does.** `designMPRA/scripts/generate12mers.R` enumerates all DNA 12-mers, then filters out sequences missing any nucleotide, containing a run of four identical nucleotides, beginning `TCT` (to avoid a junctional XbaI site), or matching a unique human mature-miRNA seed (positions 2–7). It saves the resulting `twelvemers`; the package distributes a 1,140,292-element version as documented data.
- **Interface/status.** **Development/example code, not a callable/exported user API.** The full script is reproduced in paper Supplement S5. The runtime package selects the precomputed pool; it does not rerun this generator.
- **Restrictions.** The script uses hard-coded files under `~/plateletMPRA` and a hard-coded output under `~/designMPRA`, so it is not standalone from the repository. It screens human miRNA seeds only, with exact matching as shown. Supplement prose says KpnI/XbaI sites were excluded, but the printed/current script shows no explicit internal `GGTACC`/`TCTAGA` filtering step beyond the leading-`TCT` junction filter; that paper/code discrepancy must be preserved rather than silently resolving it in favor of the prose. It does not impose pairwise Hamming/edit-distance optimization.
- **Evidence.** [`generate12mers.R` lines 1–62](https://github.com/andrewGhazi/designMPRA/blob/0cf56ee602fc86dde705906d071a39cbdf6e99a8/scripts/generate12mers.R#L1-L62); [package data documentation](https://rdrr.io/github/andrewGhazi/mpradesigntools/man/twelvemers.html); paper PDF pp. 27–28, Supplement S5.

### Phase 1 boundary observations

- The paper accurately describes the 2017 web-era headline abilities—power exploration and VCF-to-hg38 barcoded constructs—but it predates important package abilities now present in 0.2.0: a VCF indel preprocessor, asymmetric context, custom/error-correcting barcode pools, arbitrary barcode pattern filtering, optional context-site mutation, maximum-size trimming, optional TG/GGC elements, and automatic RV-tag handling.
- Conversely, paper/web properties are not automatically current package defaults: the paper's TG/GGC layout is optional and off by default in the package; its `mut` screenshot is now `alt`; the paper gives no current API signature, capacity, or current availability; and the hosted web application is no longer available.
- No source reviewed provides amino-acid/protein design, variant discovery/ranking, saturation/degenerate design, phased/combinatorial haplotype design, or automatic control-sequence generation. The generic cloning/transfection/sequencing diagram in Supplement S1.1 describes the laboratory assay, not additional software operations.

## C. BALANCE

The record is broadly balanced in space: although it enumerates more limitations than strengths, it gives the tool's genuine strengths—power analysis, VCF-to-hg38 construction, barcode pools/uniqueness, strand handling, structured failures, and restriction-site remediation—substantial and often disproportionate detail rather than burying them. Its balance is weakened by factual overstatement of several strengths (especially reproducible barcode generation, universally distinct repairs, and local Shiny usability) and by the contrary blanket denial of barcode homopolymer checking. Correcting those points would leave a fair overall portrayal rather than one systematically weighted toward either capabilities or limitations.
