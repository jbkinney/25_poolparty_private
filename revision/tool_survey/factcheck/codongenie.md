### Scope and central data model

CodonGenie is principally a designer and analyser of **one three-base IUPAC ambiguous/degenerate codon at a time**. One ambiguous codon represents a small DNA-variant set: its expansion into ordinary codons and therefore its encoded amino-acid set. The documented Design mode takes a target subset of the 20 canonical amino acids and a host organism; the documented Analyse mode takes an existing three-letter IUPAC codon and a host. The paper is explicit that the main design result is a list of **individual ambiguous codons**, potentially containing off-target amino acids, rather than a multi-codon mixture that exactly covers the targets (paper pp. 4–6, especially p. 5). The current UI likewise offers only 20 amino-acid buttons or one three-character codon plus one organism ([UI lines 46–190](https://github.com/neilswainston/CodonGenie/blob/c26439f93954d9b61b7dfccc9fd12b4936dfbcae/static/index.html#L46-L190)).

### Frozen scope boundaries relevant to later comparison

The documented CodonGenie core does **not** itself design primers/oligos, choose mutation sites, optimize an entire multi-site library globally, return a multi-codon cocktail, enforce exact absence of off-target amino acids/stops, specify nonuniform nucleotide-mixture ratios, calculate full multi-position library coverage, or export an enumerated full-length sequence collection. Its example can concatenate sitewise best codons from an alignment, and its undocumented Python utilities can reverse-translate or make one synonymous stochastic sequence at a time, but those are distinct from the documented Design/Analyse web application.

## A. FACTUALLY WRONG

1. **“Design — given a set of target amino acids + an NCBI Taxonomy ID, enumerate and rank *every* ambiguous (degenerate) codon that encodes those amino acids.”** This repeats language from the paper but is false of the current implementation. The software constructs a restricted candidate subset from hard-coded amino-acid encodings and wobble combinations; it does not test all 3,375 IUPAC triplets. A decisive current-software counterexample is target `M`: the [live API](https://codongenie.appspot.com/codons?aminoAcids=M&organism=37762) returns only `ATG`, although many ambiguous codons, including `NNN`, also expand to include `ATG` and therefore encode M. See the actual construction algorithm in [`optimise_codons`/`__analyse`](https://github.com/neilswainston/CodonGenie/blob/c26439f93954d9b61b7dfccc9fd12b4936dfbcae/codon_genie/codon_selector.py#L72-L103). The record does not flag this paper/current-software disagreement.

2. **“Its entire public surface is two operations” and “Every response is `Response(json.dumps(...), mimetype='application/json')`.”** The public service also has organism-list and organism-search operations, and `/` returns the static HTML application rather than JSON. `main.py` shows the HTML home response at [lines 40–43](https://github.com/neilswainston/CodonGenie/blob/c26439f93954d9b61b7dfccc9fd12b4936dfbcae/main.py#L40-L43), the two organism endpoints at [lines 46–58](https://github.com/neilswainston/CodonGenie/blob/c26439f93954d9b61b7dfccc9fd12b4936dfbcae/main.py#L46-L58), and the JSON codon endpoint at [lines 61–72](https://github.com/neilswainston/CodonGenie/blob/c26439f93954d9b61b7dfccc9fd12b4936dfbcae/main.py#L61-L72).

3. **“One and only one mutagenesis mode” and “No … random sampling.”** Those absolutes are false for the shipped Python package. `CodonOptimiser.mutate(protein_seq, dna_seq, mutation_rate)` stochastically retains or replaces each coding triplet with a host-usage-weighted synonymous codon, and `get_random_codon` is an explicit random sampler. These are source/package APIs rather than web/REST modes, a distinction the record should have applied to the denial as well as to its later positive capability list. Evidence: [`mutate`](https://github.com/neilswainston/CodonGenie/blob/c26439f93954d9b61b7dfccc9fd12b4936dfbcae/codon_genie/codon_utils.py#L119-L125) and [`get_random_codon`](https://github.com/neilswainston/CodonGenie/blob/c26439f93954d9b61b7dfccc9fd12b4936dfbcae/codon_genie/codon_utils.py#L135-L157).

4. **“The tool has no sequence context at all,” “There are no output sequences,” and “it … never emits sequences.”** These claims are true only of the core single-codon REST operation, not of CodonGenie as packaged. `get_codon_optim_seq` accepts a full protein and returns a full DNA sequence; `mutate` accepts paired full protein/DNA sequences and returns DNA; and the bundled alignment example returns a concatenated multi-position degenerate DNA sequence. Evidence: [`get_codon_optim_seq`](https://github.com/neilswainston/CodonGenie/blob/c26439f93954d9b61b7dfccc9fd12b4936dfbcae/codon_genie/codon_utils.py#L62-L105), [`mutate`](https://github.com/neilswainston/CodonGenie/blob/c26439f93954d9b61b7dfccc9fd12b4936dfbcae/codon_genie/codon_utils.py#L119-L125), and [`seq_from_alignment`](https://github.com/neilswainston/CodonGenie/blob/c26439f93954d9b61b7dfccc9fd12b4936dfbcae/codon_genie/example/align.py#L13-L31). The correct qualification is that the **documented web Design operation** has no sequence context.

5. **“it never enumerates variants.”** The core service does enumerate all concrete **codon-level** variants of every returned ambiguous codon in `ambiguous_codon_expansion`; the record itself reproduces this field and later calls it the “precise DNA-variant count.” What it does not enumerate is the Cartesian product of full-length, multi-position sequence variants. Evidence: [result construction](https://github.com/neilswainston/CodonGenie/blob/c26439f93954d9b61b7dfccc9fd12b4936dfbcae/codon_genie/codon_selector.py#L105-L132) and [the UI’s variant count](https://github.com/neilswainston/CodonGenie/blob/c26439f93954d9b61b7dfccc9fd12b4936dfbcae/static/result/result.html#L30-L34).

6. **“Combined with each codon's `probability` (host usage frequency), this is an explicit statement of expected variant-composition skew within the designed pool.”** CodonGenie reports genetic-code redundancy (how many expansion codons map to each amino acid) and organismal codon-usage frequencies; it does **not** model oligo-mixture proportions or predict the physical composition of a synthesized pool. The `probability` value comes from the host’s Kazusa codon-usage table, not from synthesis abundance ([fetch and normalization](https://github.com/neilswainston/CodonGenie/blob/c26439f93954d9b61b7dfccc9fd12b4936dfbcae/codon_genie/codon_utils.py#L159-L188)), and the result contains no mixture-fraction field ([result schema](https://github.com/neilswainston/CodonGenie/blob/c26439f93954d9b61b7dfccc9fd12b4936dfbcae/codon_genie/codon_selector.py#L119-L130)). A 2:1 codon-count ratio is inferable under an unstated equal-mixture assumption, but expected physical pool composition is not an output capability.

7. **“last human commit 2022-06-09” and the 2022-12-12 commit “is an automated `TrellixVulnTeam` … bot PR, not author maintenance.”** The underlying patch commit was contributed by TrellixVulnTeam, but the merge commit’s primary Git metadata names **Neil Swainston** as author and includes “Update appears to be safe to merge.” It is therefore incorrect to state as fact that no human/author activity occurred after June. The defensible maintenance fact is simply that the latest commit was the author’s 2022-12-12 merge of an external security patch and that no commits/releases followed; the project is still dormant. Evidence: [latest commit](https://github.com/neilswainston/CodonGenie/commit/c26439f93954d9b61b7dfccc9fd12b4936dfbcae) and [history](https://github.com/neilswainston/CodonGenie/commits/master/).

8. **“If Kazusa changes its page format or goes offline, a self-hosted instance silently loses all codon-usage scoring.”** It does not silently return an unscored design. `urllib.request.urlopen` and parsing are not guarded; network/parse failures propagate, and the Flask exception handler returns an HTTP 500 JSON error. The record’s following bullet correctly documents such a 500, contradicting “silently.” Evidence: [Kazusa request/parser](https://github.com/neilswainston/CodonGenie/blob/c26439f93954d9b61b7dfccc9fd12b4936dfbcae/codon_genie/codon_utils.py#L159-L188) and [server exception handler](https://github.com/neilswainston/CodonGenie/blob/c26439f93954d9b61b7dfccc9fd12b4936dfbcae/main.py#L75-L82).

## B. INCOMPLETE

1. **The alternative-genetic-code option is materially restricted.** The record notes `CodonSelector(table_id=...)` but omits that candidate generation remains hard-coded to standard-code amino-acid encodings; only the expansion’s translation lookup changes. Consequently, this is not complete alternative/augmented-code design support and can omit codons newly assigned to an amino acid or generate candidates that no longer cover the requested amino acid. Evidence: the selectable translation table at [lines 62–68](https://github.com/neilswainston/CodonGenie/blob/c26439f93954d9b61b7dfccc9fd12b4936dfbcae/codon_genie/codon_selector.py#L62-L68) versus the fixed candidate map at [lines 16–36](https://github.com/neilswainston/CodonGenie/blob/c26439f93954d9b61b7dfccc9fd12b4936dfbcae/codon_genie/codon_selector.py#L16-L36). This matters because the record’s “Alternative genetic codes” heading otherwise makes an experimental design capability appear more complete than it is.

2. **Full-sequence reverse translation is stochastic and has a constraint-relaxation mode.** Although the record name-checks `get_codon_optim_seq`, it does not explain that it returns one host-usage-weighted random synonymous DNA sequence per call; repeated calls can yield a collection of different designs. Nor does it disclose that `tolerant=True`, after exhausting attempts, progressively permits otherwise invalid repeat/restriction patterns, with behavior controlled by `max_attempts` and `stepback` ([implementation](https://github.com/neilswainston/CodonGenie/blob/c26439f93954d9b61b7dfccc9fd12b4936dfbcae/codon_genie/codon_utils.py#L62-L105)). This is material because the advertised “constraints” are not necessarily hard guarantees in tolerant mode.

3. **The synonymous mutation generator’s actual semantics and limitations are only name-dropped.** `mutate` independently decides at every residue whether to retain the input triplet or draw a usage-weighted synonymous codon; it returns one sequence, does not guarantee a requested number of changed codons, may redraw the original codon, and does not validate that the supplied DNA encodes the supplied protein ([source](https://github.com/neilswainston/CodonGenie/blob/c26439f93954d9b61b7dfccc9fd12b4936dfbcae/codon_genie/codon_utils.py#L119-L125)). These details determine what sort of variant collection repeated calls can generate.

4. **`get_cai` is not conventional sequence CAI, and a host-probability accessor is omitted.** For an arbitrary DNA sequence, the method takes an **arithmetic mean** of recognized codon relative-adaptiveness values, silently skips unrecognized/incomplete triplets, and divides by zero if none are recognized; conventional CAI is not described by this implementation. `get_codon_prob(codon)` also directly exposes the normalized host codon probability but is not mentioned. Evidence: [`get_codon_prob`](https://github.com/neilswainston/CodonGenie/blob/c26439f93954d9b61b7dfccc9fd12b4936dfbcae/codon_genie/codon_utils.py#L58-L60) and [`get_cai`](https://github.com/neilswainston/CodonGenie/blob/c26439f93954d9b61b7dfccc9fd12b4936dfbcae/codon_genie/codon_utils.py#L107-L117). This matters for interpreting both reported scores and any programmatic sequence-quality calculation.

5. **The Python client is configurable for self-hosting, but has minimal transport behavior.** `CodonGenieClient(url=...)` accepts a caller-supplied base URL rather than only the live appspot service; calls are synchronous and provide no batching, retries, authentication, API negotiation, or local fallback ([client](https://github.com/neilswainston/CodonGenie/blob/c26439f93954d9b61b7dfccc9fd12b4936dfbcae/codon_genie/client.py#L12-L46)). This is material to the record’s claim that CodonGenie is deployable and embeddable as a microservice.

6. **The alignment example’s selection semantics are incomplete.** It removes gaps (`-`) from each alignment column, takes only the first-ranked codon at every position, concatenates one IUPAC DNA string, and its organism helper returns the first substring-search hit ([example](https://github.com/neilswainston/CodonGenie/blob/c26439f93954d9b61b7dfccc9fd12b4936dfbcae/codon_genie/example/align.py#L13-L42)). This matters because it is the sole provided multi-position workflow and does not preserve alternative per-site designs or calculate the combined library.

7. **Mixed-base ratios and multi-position library arithmetic are absent.** The core interface accepts only an amino-acid set, one organism, or one three-character IUPAC codon; it has no parameter for nonuniform nucleotide-mixture fractions and does not compute or enumerate the Cartesian product across multiple designed positions ([UI inputs](https://github.com/neilswainston/CodonGenie/blob/c26439f93954d9b61b7dfccc9fd12b4936dfbcae/static/index.html#L46-L190); [REST dispatch](https://github.com/neilswainston/CodonGenie/blob/c26439f93954d9b61b7dfccc9fd12b4936dfbcae/main.py#L61-L72)). The record explains the single-codon scope but omits the mixture-ratio restriction, which is central to understanding what physical pool composition it can and cannot specify.

## C. BALANCE

The record is unusually comprehensive and gives the documented single-codon Design/Analyse strengths substantial space: scoring, exact codon expansion, off-target/stop reporting, host dependence, organism lookup, UI/REST access, examples, and obscure package utilities are all represented. It is nevertheless not fully balanced internally. Limitations are repeated across the matrix, conventions, limitation section, availability section, and conclusion, while several matrix rationales use absolute denials (“no random sampling,” “no sequence context,” “no output sequences”) that contradict the later acknowledgement of the full-sequence optimiser, stochastic mutator, and alignment example. Overall it is broadly fair to the documented web tool but somewhat limitation-heavy and understates package/example capabilities in its headline assessments.
